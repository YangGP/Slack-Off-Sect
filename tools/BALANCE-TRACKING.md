# 完整飞升测定

统一入口为 `balance:track`，复用 `pacing-scenario.mjs` 的真实游戏推进、决策策略、飞升动作和 `resource-recorder.mjs` 的资源流水。没有第二套独立模拟循环。以下命令为使用说明，本轮未执行。

```powershell
npm run balance:track -- 0 12345
```

从空白新局开始，目标为一次实际飞升，默认自然突破概率、满配可用护道、关闭事件、持续在线、每5秒执行一次参照机器人步骤；沿用既有阶段产业投资策略，香火投资默认关闭。`0` 表示最多3024游戏小时，并非无限运行。单样本累计计算预算最多7200秒；未达到目标时会报告预算或观察期限截止，不宣称不可达。

确定性经济对照可加 `--outcomes=guaranteed`；真实作息与香火路线可用：

```powershell
npm run balance:track -- 0 12345 --events=1 --faith=growth --visits=waking --decision-seconds=150 --batch-actions=12 --reserve=ready
```

同种子不保证不同策略获得相同突破结果；报告只代表指定机器人策略，不等于真人最优路线。`--visits=waking` 为每日前16小时在线、后8小时离线；离线沿用游戏有界近似，不冒充逐秒精确在线。

支持原位置参数 `[hours] [seed]`，也支持 `--hours=... --seed=...`，两种写法不能重复指定同一项。`--sample=60..1800` 控制周期快照秒数，关键节点快照不受它限制。其余护道、作息、产业、专精、转世、决策参数沿用 P1 测定。资源记录强制开启，不支持将 `--record=false` 或阶段截止 `--stop-realm` 用于本入口。

`--mode=reincarnate` 兼容入口会实际执行一次炼虚转世后停止；可用 `--reincarnate-realm=6` 改为化神。若要测转世后首飞，使用默认飞升模式加 `--reincarnations=1 --reincarnate-realm=6`。飞升模式的 `--lives=1..5` 是实际飞升次数。

## 输出

每次运行独立保存到 `.resource-records/<runId>/`，报告与完整流水同目录，不随 `npm run clean` 删除：

| 文件 | 内容 |
| --- | --- |
| `summary.md` / `summary.json` | 总耗时、完成与对账状态、阶段耗时、缺料概览及统计边界 |
| `result.json` | 完整策略、突破尝试、死亡／退境、解锁节点、飞升前后状态与结算一致性结果 |
| `stages.csv` | 按世次及境界访问分段的耗时、材料首次备齐、最后缺料及最后备齐后经过时间 |
| `resources.csv` | 分阶段各资源期初、实际增加、实际减少、期末；连续毛产出与维护模型独立列示 |
| `totals.csv` | 全程各资源的期初、实际增减、独立期末及产销模型汇总 |
| `spending.csv` / `flows.csv` | 实际离散支出去向，以及全部资源变化的来源、动作与手动／自动分类 |
| `losses.csv` | 仓容截断、取整、能量逸散、离线合并损失和重置清空，保留各自字段 |
| `blockers.csv` | 破境缺料、仓容不足、满仓、缺料资源对应加工状态、建筑降载的采样时长 |
| `samples.csv` | 周期及关键动作前后的全资源快照、仓容和产销模型；金额为十进制字符串 |
| `records-*.jsonl` | 带序号和校验和的原始动作、资源变动、状态区间与完整快照 |
| `checkpoint.json` | 在安全边界保存的可恢复状态；还有上一份检查点备份 |

所有研究、每类建筑首次建设、突破和独立重置都有关键快照；嵌套身死重置由突破前后快照覆盖。快照是否对应成功动作须结合 `action-end` 的返回结果查看。`summary.json` 的 `milestones` 给出原始快照序号。

实际增减是引擎写入库存的事实。连续生产与维护在引擎内按净额结算，因此同时发生的毛收支只标为模型；加工产量单独按配方汇总。重置发放及永久余额镜像恢复不应视为生产收入。损失已经反映于资源流水或未入库金额，不能再从期末余额扣一次。

阻塞与满仓时长按观察区间左端状态计算，在线一般为5秒边界，离线为近似边界；各资源可能同时缺料，时长不可相加为总等待。加工状态含“按当前速限运行”“待启用自动”等描述，不全部代表无法推进。材料备齐后经过时间也可能包括投资、护道或策略选择，不自动解释为机器人空等。

阶段期初期末由全局已对账流水推导；原始快照和全局期初／期末用于交叉检查。回退、身死、转世和飞升后的重复境界使用独立访问编号，重置过程归入离开的阶段。

## 暂停、恢复与重建

在记录目录放置 `STOP` 空文件，可在安全边界暂停。恢复前移除 STOP；沿用同一份已编译程序，不重建、不修改源码：

```powershell
node .smoke-balance-track/balance-telemetry.js --resume=".resource-records/<runId>/checkpoint.json"
```

恢复只允许额外调整 `--wall-seconds` 累计预算，最高7200秒；游戏观察期限、已完成目标和累计预算上限不能靠恢复绕过。源码、bundle、Node版本或记录校验不一致会拒绝恢复。新版记录器为 schema 3，旧检查点不可用于续跑新源码。

只重建报告，无需重跑游戏：

```powershell
node tools/run.mjs resource-report ".resource-records/<runId>"
```

重建会检查流水校验和与序号、独立对账，再输出 `report.rebuilt.json` 和同套汇总／CSV。有 `result.json` 时同时保留策略与结算数据；缺少时只能恢复流水中已有的事实，不能补造策略轨迹或旧版未记录的指标。

退出码：0为目标完成且对账一致，1为错误或对账不一致，2为正常停止但目标未完成。预算截止、STOP中断与观察期限截止均保留已有数据；只有实际结算目标达成才标记完成。

新版入口改用 P1 策略，默认概率也从旧遥测的必成功改为自然概率；旧 `.smoke-balance-track/` 报告继续保留，但不能与新样本直接当作同策略对照。旧遥测辅助模块 `telemetry-lib.mjs` 保留供历史代码参考，不再驱动正式测定。
