# v0.32 工业系统测试与下一步计划

日期：2026-10-11。此次仅增加测试工具与报告，没有调整游戏数值或玩法。

后续v0.33已落实瓶颈提示、动力费用试调及扩仓诊断；v0.34根据实际操作体验恢复手动即时合成，工位约束用于自动加工，旧订单保留兼容。因此下文“把手动批量纳入产线”是历史方案，已不作为待办。验证记录见[BALANCE.md](BALANCE.md)，当前规则见[CRAFT-PROGRESSION.md](CRAFT-PROGRESSION.md)。下文保留v0.32测试与当时的改进计划。

## 回归结果

`npm run check`通过：1268项引擎检查（含48项工业专项）、19项SSR检查、342项DOM检查。`npm run build`成功。

另新增`npm run check:industry`，执行10分钟连续加工、供能中断、多工位共享预算、在线／离线对照及双极满仓供料实验。实验使用预先配置的设备、研究、大容量仓储和原料，用于隔离机制；不能当作自然玩家的生产能力或通关成绩。

| 实验 | 结果 |
| --- | --- |
| 相同设备、充足原料，普通加工600秒 | 玄钢672，完成1200基础加工秒 |
| 同条件灵气超载600秒 | 玄钢1346，完成2400基础加工秒；额外动力流量积分600灵气 |
| 同条件灵能驱动600秒 | 玄钢1346，完成2400基础加工秒；额外动力流量积分120灵能 |
| 灵能库存5、停用湮灭炉 | 600秒内完成1208基础加工秒，动力耗尽后回落到普通加工，玄钢677 |
| 五组工位共用4供能、5冷却 | 灵能驱动合计只使用4额外容量，各工位分得0.8；超载合计使用5冷却容量 |
| 多工位灵能驱动，120秒在线与离线 | 全部资源库存一致，误差小于0.000001 |
| 正灵子满仓、负灵子为零，偏极阵2座、湮灭炉1座 | 连续600秒分流负荷50%，满仓侧库存不增长，少的一侧即产即用，湮灭炉持续产能 |

连续实验未观察到负库存、非有限库存、共享预算超支或双极满仓白耗料。动力流量积分是界面计划速率的积分，断供跨越的秒内可能与实际扣费略有不同；逐事件实际扣费由工业专项检查验证。

0仙缘日志与留存的v0.31同种子日志完全一致，包含里程碑与最终库存，不能把这次停滞归因于v0.32动力改造。202仙缘样本中多次身死重开，单次终态不能用来推断平均推进速度。两组都没有走到灵能，因此尚未实测移除库存倍率后的自然后期节奏。

既有玩家脚本会每5秒手动批量制作，并且不会选择超载或灵能驱动；它适合发现整体推进停滞，无法独立衡量自动工位的价值。0仙缘最终灵气分子库存100，也需要进一步核查下一境材料要求、扩仓前置与脚本护道策略；目前不把具体根因认定为游戏死锁。

## 下一步改进顺序

1. **先补齐推进诊断。** 模拟输出每阶段的缺料、容量缺口、关键研究前置与破境失败统计；让脚本按库存保留和实际负荷使用驱动。用多个种子，分别统计自然失败路线与隔离失败的产业路线，直到实际投产湮灭炉并完成阵印。验收：能够解释合体停滞，并获得后期动力运行与首飞样本。
2. **把手动批量纳入产线。** 手动批量改为提交加工订单，与自动补库共用工位；单件救急另定明确边界。验收：频繁点击不能绕过设备、动力与冷却容量，正常离线推进不受影响。这是下一轮游戏改造的优先项。
3. **重调动力的取舍。** 当前10分钟超载仅增加600灵气动力成本，却增加674玄钢；对照淬钢每份120灵气，用能压力很低。灵气超载与灵能驱动提供相同容量上限，灵能驱动还需要供能设施，使用理由不足。先比较单位成品的总耗气、耗能与设备投入，再考虑高阶配方更高功率需求或灵能独有的效率优势，暂不凭单个样本直接提高所有费用。
4. **让扩产瓶颈可见。** 增加上游供料、工位、动力、冷却和仓储之间的瓶颈提示，以及维持费与加工费分列。支持生产优先级或负荷上限，方便优先保障阵印与关键建材。验收：玩家能从界面判断该扩建哪类设备以及扩产后的持续耗料。

先修正诊断与手动批量绕过问题，再根据真实产线数据调整动力数值。独立冷却建筑、废热回收和更多材料等级留待现有经营选择成立后引入。
