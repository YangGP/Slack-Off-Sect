# 猫国首次重置测量

猫国专用工具集中在本目录：`first-reset.mjs` 为测量入口，`check.mjs` 为适配检查，`lib/` 保存引擎适配、机器人及库存预算。与摸鱼宗门首次转世的对比见[节奏比较](COMPARISON.md)。npm命令保持不变，均从项目根目录运行。

直接加载本地 `cat-zh-master/` 的游戏引擎，从零猫、零资源推进新局。该目录需要自行保留；当前被 Git 忽略，脚本不会下载源码。项目根目录先执行 `npm ci` 安装既有依赖。

猫国的重置入口开局就有，必须先定义终点：36只猫重置开始获得业力，71只猫重置开始按人口获得 Paragon。默认测到71只猫后调用原版重置入口，核对本次人口收益、原有 Paragon 留存、业力累计、首次重置计数及清空状态。71是按人口重置获得正 Paragon 的最低门槛，不表示推荐真人在此首转；原版每千年的额外 Paragon 奖励照常结算，不能把它误算成人口重置收益。

## 运行

在项目根目录执行：

```powershell
npm run balance:kittens -- --wall-seconds=1800
```

默认种子12345、目标71只猫、游戏观察上限720小时、本次计算预算1800秒。达到目标才算完成；`wall-budget` 只是计算预算用完，`horizon` 只是观察期结束，都不能写成不可达。

若只测最早出现业力收益：

```powershell
npm run balance:kittens -- --kittens=36 --wall-seconds=1800
```

可调整 `--kittens=36..200`、`--hours`（大于0且不超过8760）、`--seed=1..4294967295`、`--decision-seconds=1..60`、`--wall-seconds`（大于0且不超过7200）、`--source=cat-zh-master`、`--out=.resource-records/kittens`。默认每5游戏秒决策。机器人围绕基础住宅、农牧、采矿、木料、工艺和仓储发展，尚未实现贸易、宗教和太空路线；较高人口目标只是允许配置，不保证当前策略能在观察期内达到。

当前策略为 `first-reset-v6-employed-food`。保留现有的开局、研究、派工及住宅规划，参考小猫科学家的库存预算机制；具体差异见下节。v6在全部岗位分配完后重新核对粮食净产，计入幸福度对已就业猫的额外消耗，必要时将其他岗位转为农民。旧策略因偏选超仓容茅屋而长期扩仓的样本只作为诊断，不当作正常首转节奏；不同策略及源码摘要的样本禁止续接或混算。

## 小猫科学家参考范围

参考用户指定的 [Kitten Scientists 中文项目](https://github.com/zhaolinxu/kitten-scientists-zhs)，固定提交 `fcd5efc302700141cd6a4ea4c6e46394fa5d0c83`（2019-06-19），重点阅读 `kitten-scientists.user-1.3.3.js` 的库存、加工和建造逻辑。仅参考机制并按本地接口重新实现，不加载或执行该远端脚本。

- **统一库存预算**：所有购买和备料先扣保留量。口粮使用原版产量计算器，在当前岗位和加成下估算天气系数0.1的冬季净产，预留一整个冬季及一次决策间隔的缺口，与基础库存取较大值；预测不改变真实日历、缓存或随机流。仓容不足时可支配库存为0，不把保留量强行压低。
- **保护开局和幸福度**：先有20块田和2000猫薄荷，再筹备首屋；统一住宅入口也检查这个条件。保留 `max(100, 猫数×5)` 毛皮，避免备纸耗尽奢侈品。这里没有照搬 KS 的固定1000毛皮设置。
- **区分备料和顺手加工**：目标费用可以使用全部可支配库存；顺手加工在有上限的原料达到95%仓容后，仅使用可支配余量的60%，还须给近期住宅留材料。梁、石板、铁板和羊皮纸只备少量库存；产量加成纳入成品仓容检查。
- **限制常规投资**：已有基础设施后，常规扩建等主资源达到75%仓容再考虑；首座设施、定向备料和必要扩仓仍可提前进行。人力达到95%仓容后集中狩猎。

这些是本测试机器人的配置，不等于原版 KS 的全部默认设置。例如其 README 与1.3.3源码的狩猎阈值就不同。该脚本没有提供自动派工，旧的冬储函数签名、工艺名称和界面访问方式也不能直接用于本地引擎；因此没有将其当作能独立从零游玩的完整玩家。

## 暂停和继续

启动时打印本次唯一目录 `.resource-records/kittens/<runId>/`，每游戏小时保存检查点。按 Ctrl+C、计算预算到期，或在该目录新建 `STOP` 文件，都会保存当前进度和部分报告。

```powershell
New-Item -ItemType File '.resource-records/kittens/<runId>/STOP'
```

继续时先移除自己创建的 `STOP`，再指定检查点；恢复时只允许覆盖本次计算预算：

```powershell
Remove-Item -LiteralPath '.resource-records/kittens/<runId>/STOP'
npm run balance:kittens -- --resume=.resource-records/kittens/<runId>/checkpoint.json --wall-seconds=1800
```

预算按每次运行计算，报告同时保留累计计算耗时。完成重置的样本不能再恢复。恢复会核对 Node 版本和游戏/机器人脚本 SHA-256；修改策略后请从新样本开始。本次迁入 `tools/kittens/` 后源码路径和入口摘要改变，迁移前的旧检查点不能用新入口直接续跑；历史结果及当时源码归档继续保留，不改写为新路径。游戏使用原生存档恢复，会重新计算缓存，部分临时进度不在原生存档内，因此恢复样本不承诺与不停机样本逐 tick 相同。严格比较优先采用从头连续运行的样本。

## 阅读结果

- `summary.md`：是否完成、停止原因、36/71/130只猫节点、人口、死亡与重置结算。
- `result.json`：参数、本地包/构建元信息、源码摘要、初始/最终及逐小时快照、首次动作时点、动作计数、节点时间和重置前后状态。元信息可能与游戏页面版本标识不同，精确比较以源码摘要为准。
- `checkpoint.json`：原版游戏存档、随机流和机器人进度，仅未完成样本用于续跑。
- `reset-save.json`：达到目标后真实重置产生的原生存档对象，供核对结算。
- `completed.json`：已完成标记，阻止用旧检查点重复恢复。
- `error.json`：发生异常时保留错误及现场，异常退出不得算完成。

退出码：0表示完成真实重置，2表示预算/观察期/主动暂停，1表示异常。日志每约30计算秒输出一次进度；最终以 `result.json` 的 `completed`、`stopReason` 和 `settlement.verified` 为准。

报告的 `simulatedHours` 是**累计在线等效小时**：原版每现实秒5 tick，每游戏年800现实秒。脚本逐 tick 计算，没有提升产量或缩短游戏时钟；计算耗时 `wallSeconds` 只表示机器执行速度。不能把游戏历法中的年数当成现实年数，也不能把计算耗时当成真人等待时间。

机器人在前10分钟或缺粮应急时每次至多采集5次猫薄荷，研究、购买、派工、加工、狩猎、观察均调用原版动作；一次决策可能含多个动作，不等于一次鼠标点击。随季节调整农民，其余劳力按固定权重分配；集中狩猎，按库存预算制作少量羊皮纸。未赠送猫、资源、科技或永久收益。报告保留饥饿死亡；有明显策略卡顿的试跑仅用于调试，不能据此推断玩家正常首转时间。结算中的 `karmaKittens` 是原版业力累计计数，不应直接当成显示的业力点数。

隔离 DOM、禁用联网和页面展示，不读取或覆盖浏览器里的玩家存档。固定种子结果代表本地这份源码和这套机器人策略，不是最优解或真人平均时间；与摸鱼宗门对照时还需统一在线作息和操作频率。

快速验证适配层及库存预算：`npm run check:kittens`。它检查空白新局、真实扣费/生产/日历、冬储预测只读性、原料/仓容预算及全部派工后的口粮消耗，并用明确的人口夹具验证真实重置结算；夹具不参与耗时测量。
