# 符文科技线设计

日期：2026-10-10。第一版实现范围：研究、配方、资源说明、解锁关系；不增加库存资源。

## 核心规则

符文是固定成特定形状的灵气结构。符文决定效果，材料决定承载能力，组合方式决定产物。符文属于可掌握的技术，不是要反复制造的库存物品。实体刻纹载体采用灵木与金属：基础符箓使用灵木符牌，高阶灵符使用玄钢符牌，阵基使用木板与玄铁组合。灵液负责注灵，香火辅助定纹，均不是实体载体。符箓不能作为所有刻纹工艺的通用中间材料。

符箓堂承担灵木与金属上的刻纹工艺。现有符箓及其建筑、事件、研究用途继续保留；本版不拆分聚气符、镇守符等库存，待出现独立消耗玩法再扩展。

## 科技推进

| 阶段 | 研究 | 用途与前置 |
| --- | --- | --- |
| 早期 | 符文入门（原符箓入门） | 识别并固定简单灵气结构，开放符箓堂和基础符箓 |
| 金丹 | 聚气纹 | 符文入门；灵气产出 +10%，为导灵刻纹提供基础 |
| 金丹 | 固形纹 | 符文入门；开放稳定刻纹的理论，是阵基、凝晶的前置 |
| 金丹 | 导灵纹 | 聚气纹、固形纹；开放材料之间的灵气传导，是阵基装配的前置 |
| 元婴 | 镇守纹 | 固形纹；是炼虚镇岳符的前置，不重复增加一份防灾数值 |
| 元婴 | 纳灵纹 | 固形纹、凝气成液、淬玄工艺；开放灵符配方，以玄钢载体容纳复杂符文 |
| 化神 | 复合符文 | 导灵纹、纳灵纹；开放灵器配方，把多个符文连成相互协作的结构 |
| 炼虚 | 符法精微 | 复合符文、镇守纹；开放镇岳符，代表立体符文结构的进一步掌握 |

阵基装配、凝晶工艺仍是独立的材料应用研究。凝晶工艺需固形纹，晶纹精修负责提高成品率。须弥纳芥增加纳灵纹前置，使储存技术与符文原理相连。

## 配方

以下为每次制作的基础投入，制作加成与小数结转照常适用。

| 产物 | 调整前 | 第一版配方 | 技术与场所 |
| --- | --- | --- | --- |
| 符箓 | 灵木125、灵气60 | 不变 | 符箓堂；在灵木符牌上刻入简单符文 |
| 阵基 | 木板25、符箓25、玄铁100 | 木板10、玄铁100、灵气300 | 金丹、阵基装配、符箓堂；直接刻入导灵与固形纹 |
| 灵晶 | 灵液3、符箓10 | 灵液3、灵气300 | 元婴、凝晶工艺、符箓堂；以固形纹固定结晶边界 |
| 灵符 | 符箓100、香火500 | 玄钢2、灵液2、灵气300、香火200 | 元婴、纳灵纹、符箓堂；玄钢承载符文，灵液注灵，香火辅助稳定意念 |
| 灵器 | 法器100、玄钢25 | 材料数量不变 | 化神、复合符文、炼器坊；将复合符文刻入器物 |

香火只辅助灵符的稳定与立愿，不作为承载符文的实体材料。基础法器仍可在早期制作；复合符文限制的是高阶灵器。灵宝保留器、丹、符三条支线汇合的结构。

## 平衡目标与限制

阵基去掉符箓套娃并减少木板消耗，降低金丹设施的木材投资。灵晶从消耗符箓转为消耗灵气，强化元婴的灵气生产需求。灵符不再用百张符箓堆量升级，而是从灵木载体升级到玄钢载体，串联符文与金属加工研究；灵器正式放在化神。

这会显著降低高级符阵的木材需求，不能沿用调整前的时间测量。验证应覆盖实际研究解锁、制作扣料、自动制作、建筑可达性及完整推进模拟。节奏模拟是机器人策略下的结果，不能直接等同于玩家通关时间。

暂不扩展自由绘符、符文插槽、符纸/灵墨库存、独立符箓消耗按钮，也不改变防灾计算。这些玩法需要单独设计界面和用途。

## 第一版验证结果

2026-10-10，载体修订前：编码检查、858 项逻辑检查、19 项渲染检查、262 项 DOM 检查及生产构建通过；40 种建筑全部可达。新增检查覆盖金丹符文的顺序研究、元婴灵符的解锁与实际扣料、化神灵器的研究门槛，以及炼虚符法精微的镇守纹前置。

载体修订前的常规机器人模拟（72 小时上限，仙缘 0，祭炼 0，事件关闭）：金丹 13.61 小时、元婴 19.21 小时、化神 25.06 小时、炼虚 29.00 小时、合体 30.60 小时、大乘 36.17 小时、渡劫并满足飞升条件 43.06 小时。推进没有卡住。这是当时配方与机器人策略下的单次基准，不代表实际玩家通关时间，也不能直接将与历史结果的差值全部归因于符文调整。

灵木/金属载体修订后：858 项逻辑检查、19 项渲染检查、262 项 DOM 检查、编码检查与生产构建通过，40 种建筑全部可达。同参数常规机器人模拟：金丹 13.61 小时、元婴 19.21 小时、化神 25.06 小时、炼虚 29.00 小时、合体 30.34 小时、大乘 34.32 小时、渡劫并满足飞升条件 40.93 小时。金丹至炼虚节奏保持该模拟原有水平，后期节奏随灵符用料及机器人投资选择变化，未发现推进卡点。

后续晶核阵定位与防护分工调整见 [ARRAY-ROLES.md](ARRAY-ROLES.md)。本页验证时间保留为符文载体版本的历史基准。
