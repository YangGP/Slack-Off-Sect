# [Feature Request] 弟子养成系统扩展：修炼、突破、灵根与天赋

## 一、需求背景

当前弟子系统主要承担资源生产中的劳动力分配功能。玩家将弟子分配至不同岗位以获得资源产出，但弟子之间缺乏个体差异，也没有独立、持续的成长机制。

建议在保留现有岗位分配系统的基础上，分阶段引入修炼、突破、灵根与天赋机制，使弟子逐步从可替换的生产单位，转变为具有成长性、个体差异和长期培养价值的角色。

### 核心目标

- **成长反馈**：弟子能够随时间持续成长。
- **经营关联**：弟子成长直接影响现有资源生产效率。
- **个体差异**：通过灵根和天赋形成不同的培养价值。
- **策略深度**：通过突破成本与风险增加资源决策。
- **低操作负担**：保持放置经营体验，避免繁琐的角色管理。
- **复用现有机制**：优先使用游戏已有的境界、资源与岗位体系。

### 设计原则

- 按阶段逐步引入复杂度，每次迭代保持明确的最小交付范围。
- 修炼过程尽量自动化，玩家主要参与岗位分配、突破时机与资源规划。
- 弟子养成服务于资源经营，不发展成脱离经营系统的独立 RPG 系统。
- 境界、灵根、突破和天赋各自承担清晰、不同的功能。

## 二、迭代规划

### 迭代一：弟子列表、修为与自动修炼系统 `P0`

**目标：建立独立的弟子个体数据和成长机制，使弟子不再只是岗位上的数量。**

#### 1. 详细弟子列表

新增详细弟子列表，展示每名弟子的独立信息。

| 字段 | 说明 |
|---|---|
| 姓名 | 弟子生成时可随机获得修仙风格姓名 |
| 境界 | 复用游戏已有境界体系 |
| 当前修为 | 当前累计修为值 |
| 修炼进度 | 当前境界内的修炼进度 |
| 修炼速度 | 单位时间内获得的修为 |
| 当前岗位 | 弟子当前被分配的工作 |
| 生产加成 | 由弟子境界提供的生产效率加成 |

建议支持按照境界、修为和岗位等字段筛选或排序，方便后期管理大量弟子。

姓名初期仅作为展示信息，不影响实际数值。后续引入灵根和天赋后，可继续在弟子列表或详情页扩展相应信息。

#### 2. 随机姓名

- 弟子生成时，从预设姓氏库和名字库中随机组合姓名。
- 姓名应持久化保存，重新加载存档时不得变化。
- 初期不要求姓名唯一，后续可视体验决定是否增加重名处理或改名功能。
- 随机姓名属于可选增强项，不应阻塞修为和境界主流程交付。

#### 3. 自动修炼

第一阶段所有弟子采用统一的线性修炼机制：

- 所有弟子的初始修炼速度相同。
- 修为随游戏时间自动增长。
- 修炼不消耗额外资源，也无需玩家主动操作。
- 弟子被分配到岗位后仍可正常修炼。
- 支持离线修炼，沿用现有游戏的离线时间计算逻辑。
- 本阶段暂不考虑灵根、天赋或环境造成的速度差异。

```text
当前修为 = 初始修为 + 基础修炼速度 × 修炼时间
```

#### 4. 复用已有境界体系

游戏当前已有境界体系，本需求不重新设计境界名称和层级，只为现有境界补充弟子成长与生产关联。

第一阶段暂不启用突破限制。弟子修为达到下一境界要求后，自动晋升至下一境界。

#### 5. 境界与生产效率关联

为已有的不同境界配置相应生产效率加成：

```text
弟子实际产出 = 岗位基础产出 × 境界产出系数
```

境界越高，弟子在岗位上的生产效率越高。具体系数需要结合现有资源经济体系进行平衡，并支持通过配置调整。

本阶段重点建立以下关系：

```text
弟子个体
  ├── 姓名
  ├── 当前岗位
  ├── 当前修为
  ├── 当前境界
  └── 生产效率
        └── 受境界影响
```

需要将现有岗位分配逻辑与独立弟子数据关联，为后续突破、灵根和天赋提供扩展基础。

#### 验收标准

- [ ] 新增详细弟子列表，并展示本阶段要求的核心字段。
- [ ] 每名弟子拥有独立、可持久化的修为和境界数据。
- [ ] 可选：弟子生成时随机获得姓名，读取存档后姓名保持不变。
- [ ] 所有弟子按照统一速度自动修炼。
- [ ] 岗位工作不影响本阶段的基础修炼。
- [ ] 离线期间的修为增长计算正确。
- [ ] 修为达到要求后自动提升至已有体系中的下一境界。
- [ ] 不同境界正确提供相应的资源产出加成。
- [ ] 现有岗位分配与资源生产机制保持正常。

### 迭代二：境界突破系统 `P1`

**目标：在自动修炼的基础上引入突破成本、成功率和失败惩罚，并根据境界阶段逐步提高突破风险。**

#### 1. 突破条件

启用突破系统后，弟子修为达到当前境界上限时不再自动晋升，而是进入待突破状态。

突破需要满足：

- 修为达到当前境界上限。
- 消耗一定数量的指定资源。
- 满足当前境界对应的其他突破条件（如有）。

不同境界的突破成本和成功率应分别配置。

#### 2. 突破风险分级

将已有境界划分为初级、中级和高级三个风险阶段。具体划分根据现有境界体系、游戏进度和数值平衡确定。

| 阶段 | 突破成本 | 失败惩罚 | 设计目的 |
|---|---|---|---|
| 初级境界 | 较低 | 损失突破材料、部分修为，可附加短暂冷却 | 降低前期养成门槛 |
| 中级境界 | 中等 | 初级惩罚，并有概率进入境界停滞 | 引入长期培养风险 |
| 高级境界 | 较高 | 中级惩罚，并有较低概率身死道消 | 增加高阶突破的风险收益权衡 |

#### 3. 初级境界：基础惩罚

- 突破失败消耗对应材料。
- 损失一定比例的当前修为。
- 可进入短暂的突破冷却期。
- 不影响弟子的长期成长潜力。

#### 4. 中级境界：境界停滞

中级境界突破失败时，在基础惩罚之外，有一定概率触发「境界停滞」。

- 停滞期间无法再次突破。
- 可通过等待一定时间或消耗指定资源解除。
- 停滞时间或解除成本可以随境界提高。
- 不建议设置永久停滞，以免弟子彻底失去培养价值。

#### 5. 高级境界：身死道消

高级境界突破失败时，在前述惩罚基础上，有较低概率触发「身死道消」。

- 弟子永久消失，无法继续修炼或参与生产。
- 对应岗位自动释放。
- 该弟子的修为、境界、灵根和天赋等数据随之失效。
- 身死道消概率应显著低于普通失败概率。
- 发起高级突破前，界面必须明确提示永久损失风险。

#### 6. 概率机制

突破成功率与失败后的特殊惩罚概率应分开配置：

```text
发起突破
   │
   ▼
消耗突破资源
   │
   ▼
判定突破是否成功
   │
   ├── 成功 → 境界提升并更新生产加成
   │
   └── 失败
        │
        ▼
    根据境界阶段判定惩罚
        │
        ├── 初级 → 基础惩罚
        ├── 中级 → 基础惩罚 / 境界停滞
        └── 高级 → 基础惩罚 / 境界停滞 / 身死道消
```

突破成功率、境界停滞概率和身死道消概率均应支持独立配置，便于后续进行数值调整。

#### 7. 操作与交互

采用**自动修炼 + 手动突破**模式：

- 修为达到上限后，弟子自动进入待突破状态。
- 玩家自行选择突破时机。
- 突破界面展示所需资源、成功率和可能的失败惩罚。
- 高级突破需要额外显示身死道消风险并要求确认。
- 后续可增加批量突破或自动突破；涉及永久死亡时，应提供独立开关或确认机制。

#### 验收标准

- [ ] 修为达到上限后，弟子进入待突破状态并停止自动晋升。
- [ ] 不同境界拥有可独立配置的突破成本和成功率。
- [ ] 已有境界可配置为初级、中级或高级风险阶段。
- [ ] 初级突破失败正确触发材料、修为或冷却等基础惩罚。
- [ ] 中级突破失败有概率触发境界停滞。
- [ ] 境界停滞可按照配置的方式解除。
- [ ] 高级突破失败有较低概率触发身死道消。
- [ ] 身死道消后正确移除弟子并释放其岗位。
- [ ] 突破界面正确展示成功率、资源成本和风险提示。
- [ ] 突破成功后正确更新境界、状态及生产加成。

### 迭代三：灵根系统 `P2`

**目标：引入先天资质差异，使不同弟子拥有不同的修炼速度和长期培养价值。**

#### 1. 灵根分层

参考常见修仙题材设定，可采用以下分类：

| 灵根类型 | 定位 | 修炼速度系数（示例） |
|---|---|---:|
| 天灵根 | 极高资质 | 2.0 |
| 异灵根 | 优秀资质 | 1.6 |
| 双灵根 | 较高资质 | 1.3 |
| 三灵根 | 普通资质 | 1.0 |
| 四灵根 | 较低资质 | 0.8 |
| 五灵根 | 较差资质 | 0.6 |

具体命名和分类可根据游戏世界观调整。初期灵根只影响修炼速度，不引入五行克制、功法适配等复杂机制。

#### 2. 灵根随机生成

每名弟子生成时，根据配置权重随机获得一种灵根，并以随机轮盘表现抽取过程。

| 灵根类型 | 出现概率（示例） |
|---|---:|
| 天灵根 | 1% |
| 异灵根 | 4% |
| 双灵根 | 10% |
| 三灵根 | 25% |
| 四灵根 | 30% |
| 五灵根 | 30% |

- 轮盘仅用于视觉表现，实际结果由权重配置决定。
- 批量招募时应支持跳过动画。
- 灵根结果必须持久化，重新读取存档时不得重新随机。

#### 3. 修炼速度关联

```text
实际修炼速度 = 基础修炼速度 × 灵根修炼系数
```

各系统职责保持清晰：

- 境界：决定当前生产能力。
- 灵根：决定修炼成长速度。
- 突破：决定成长成本与风险。

#### 验收标准

- [ ] 每名弟子拥有独立、可持久化的灵根数据。
- [ ] 新弟子根据配置权重随机获得灵根。
- [ ] 提供灵根随机轮盘表现，并支持跳过动画。
- [ ] 不同灵根正确影响实际修炼速度。
- [ ] 弟子列表或详情页展示灵根信息。
- [ ] 灵根概率和修炼系数支持配置。

### 迭代四：特殊天赋系统 `P3`

**目标：通过随机天赋词条进一步增强弟子的个体差异、岗位价值和培养潜力。**

#### 1. 天赋生成规则

- 每名弟子生成时随机获得 **0～2 个天赋词条**。
- 每次成功突破境界时，有一定概率额外获得 **1 个天赋词条**。
- 设置合理的天赋数量上限，避免后期无限叠加。
- 默认不允许重复获得完全相同的天赋。

#### 2. 天赋等级

建立统一天赋库，按照「天地玄黄」四级分类：

| 等级 | 稀有度 | 效果定位 |
|---|---|---|
| 天 | 极稀有 | 显著增益或特殊机制 |
| 地 | 稀有 | 较强的专项增益 |
| 玄 | 普通 | 中等幅度增益 |
| 黄 | 常见 | 基础增益 |

#### 3. 双阶段随机机制

每次生成天赋时进行两次随机：

1. 按配置权重从天、地、玄、黄中随机确定天赋等级。
2. 从对应等级的天赋池中随机抽取一个具体词条。

```text
生成天赋
   │
   ▼
随机天赋等级
   │
   ├── 天级
   ├── 地级
   ├── 玄级
   └── 黄级
        │
        ▼
  对应等级天赋池
        │
        ▼
    随机具体天赋
```

该机制将稀有度控制与具体内容解耦，便于后续持续扩展天赋库。

#### 4. 天赋效果

优先围绕现有游戏机制设计天赋，不额外引入复杂系统。

| 天赋名称 | 等级 | 效果示例 |
|---|---|---|
| 天道眷顾 | 天 | 修炼速度 +30% |
| 丹道圣手 | 地 | 炼丹相关产出 +25% |
| 修炼奇才 | 玄 | 修炼速度 +10% |
| 勤勉 | 黄 | 所有岗位产出 +5% |

天赋效果可覆盖：

- 修炼速度加成。
- 突破成功率加成。
- 指定岗位生产效率加成。
- 全局生产效率加成。
- 特定资源消耗减免。

天赋尽量自动生效，不增加玩家的日常操作负担。

#### 5. 突破获得新天赋

弟子每次成功突破时进行一次额外天赋判定。判定成功后，按照上述双阶段随机机制生成新天赋。

天赋获取概率、数量上限和具体效果均应支持独立配置。突破失败获得特殊天赋可作为未来扩展，不纳入本阶段。

#### 验收标准

- [ ] 新弟子随机获得 0～2 个天赋。
- [ ] 建立天地玄黄四级天赋库。
- [ ] 天赋按照先等级、后具体词条的流程随机生成。
- [ ] 重复天赋和数量上限按照配置正确处理。
- [ ] 不同天赋正确影响对应的游戏机制。
- [ ] 成功突破时有概率获得新天赋。
- [ ] 弟子列表或详情页展示天赋名称、等级和效果。
- [ ] 天赋概率、数量上限及具体效果支持配置。

### 迭代五：独立属性系统 `P4 / 暂缓`

**建议：暂不纳入正式开发计划，待前四个迭代完成并验证后再评估。**

潜在属性可以包括力量、体质、悟性、神识和气运等，但现阶段不建议引入。

#### 暂缓原因

1. **系统复杂度过高**  
   引入属性后，需要重新定义属性与境界、灵根、天赋、岗位之间的关系，容易产生功能重叠和数值平衡问题。

2. **玩家操作成本增加**  
   如果加入手动加点或属性培养，玩家需要频繁管理每名弟子；弟子数量增加后，操作成本会快速上升。

3. **边际收益有限**  
   前四个迭代已经能够形成完整的轻量养成框架：

   ```text
   境界 → 当前生产能力
   灵根 → 修炼成长速度
   突破 → 成长成本与风险
   天赋 → 个体差异与特殊能力
   ```

   独立属性未必能提供足够的新策略，反而可能使系统过度复杂。

#### 后续评估条件

前四个阶段上线后，再根据以下问题决定是否重启本迭代：

- 弟子之间是否已经形成足够的个体差异？
- 现有培养体系是否具备足够的策略深度？
- 玩家是否明确需要进一步细化角色养成？
- 新属性能否提供不同于境界、灵根和天赋的新决策？

若未来确实需要引入属性，建议优先采用**自动成长、不可手动加点**的轻量方案。

#### 验收标准（评估阶段）

- [ ] 收集前四个迭代上线后的玩家反馈和行为数据。
- [ ] 明确独立属性所解决的问题，且不与现有系统重复。
- [ ] 完成操作负担和数值复杂度评估。
- [ ] 在满足上述条件前，不进入正式开发。

## 三、整体迭代优先级

| 阶段 | 核心功能 | 核心价值 | 开发复杂度 | 优先级 |
|---|---|---|---|---|
| 迭代一 | 详细弟子列表、随机姓名、修为、自动修炼、境界产出加成 | 建立弟子个体与成长体系 | 低～中 | P0 |
| 迭代二 | 突破成本、成功率、分级失败风险 | 增加经营决策与成长风险 | 中 | P1 |
| 迭代三 | 灵根分层、随机轮盘、修炼速度差异 | 建立先天资质差异 | 低～中 | P2 |
| 迭代四 | 天赋库、随机词条、突破获得天赋 | 增加角色个性与策略深度 | 中～高 | P3 |
| 迭代五 | 独立属性系统 | 进一步深化角色养成 | 高 | 暂缓 |

## 四、通用实现建议

### 1. 弟子作为独立实体

建议从迭代一开始就将弟子作为独立实体管理，并提前预留后续字段。

| 字段 | 含义 | 引入阶段 |
|---|---|---|
| `discipleId` | 弟子唯一标识 | 迭代一 |
| `name` | 弟子姓名 | 迭代一 |
| `roleId` | 当前岗位 | 已有 / 迭代一关联 |
| `cultivation` | 当前修为 | 迭代一 |
| `realm` | 当前境界 | 迭代一 |
| `cultivationRate` | 实际修炼速度，可动态计算 | 迭代一 |
| `breakthroughStatus` | 待突破、停滞等状态 | 迭代二 |
| `spiritualRoot` | 灵根类型 | 迭代三 |
| `talents` | 天赋词条列表 | 迭代四 |

境界、灵根和天赋的数值与效果应抽离为独立配置，避免直接硬编码在弟子数据中。

### 2. 统一计算入口

建议统一管理各系统对修炼速度与生产效率的影响。

```text
实际产出 = 岗位基础产出 × 境界系数 × 天赋产出系数

实际修炼速度 = 基础修炼速度 × 灵根系数 × 天赋修炼系数
```

公式用于表达机制关系；最终采用乘法、加法或设置上限，应根据数值平衡结果确定。

### 3. 保持低操作负担

随着弟子数量增长，建议逐步提供以下体验优化：

- 按境界、灵根、岗位和天赋筛选、排序。
- 批量突破。
- 自动突破及风险等级开关。
- 根据境界和天赋自动推荐或分配岗位。

这些功能不必全部进入第一阶段，但数据与界面设计应避免阻碍后续扩展。

### 4. 控制数值膨胀

境界、灵根和天赋可能形成多层加成。各项系数应支持配置，并在每个阶段结合现有资源体系进行模拟和平衡，必要时设置边际收益或总加成上限。

### 5. 存档兼容性

- 新增字段必须提供合理默认值，确保旧版本存档能够加载。
- 姓名、灵根和天赋等随机结果需要持久化。
- 需要明确旧弟子升级存档时的初始化规则。
- 不得因重复读取存档而重新随机属性。

### 6. 离线修炼

修为增长应根据经过时间计算，而不是依赖界面刷新次数。需要明确离线修炼时长上限，以及弟子在离线期间达到突破条件后的处理方式；默认建议在达到当前境界上限时停止累积，等待玩家突破。

---

## 五、总结

建议按照以下顺序逐步实现：

```text
独立弟子与自动修炼 → 境界突破 → 灵根资质 → 随机天赋
```

- **迭代一是基础**：建立详细弟子列表，以及弟子与姓名、岗位、修为、已有境界和生产效率之间的关系。
- **迭代二是决策**：通过分级突破风险，使成长与资源经营发生联系；初级采用基础惩罚，中级引入境界停滞，高级引入身死道消。
- **迭代三是差异**：通过灵根使弟子拥有不同的成长速度。
- **迭代四是深度**：通过天地玄黄天赋库和随机词条，使弟子形成不同的岗位价值和培养潜力。
- **迭代五暂缓**：待前四个阶段验证后，再判断独立属性是否有必要。

前四个阶段可以逐步完成从「单纯的劳动力分配」到「具有成长性和个体差异的弟子养成」的转变。

> **核心原则：让弟子系统有成长、有差异、有策略，但不要让玩家陷入繁琐的角色管理。**
