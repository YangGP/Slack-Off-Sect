# 游戏设计与当前规则（v0.14）

更新：2026-10-09。本文描述当前实现。完整条目、费用与门槛由 [TABLES.md](TABLES.md) 从源码生成；修真、工艺与境界的依赖审视见 [CULTIVATION-REVIEW.md](CULTIVATION-REVIEW.md)。历史平衡与测量保存在 [BALANCE.md](BALANCE.md)，未实施方向见 [ROADMAP.md](ROADMAP.md)。

## 1. 定位与设计目标

纯前端宗门放置经营游戏，参考猫国的资源池、劳动力分配、叠加建筑和加工体系。主要决策是生产分工、研究投资、加工目标、营造扩仓与重置时机。当前境界属于宗门整体，没有弟子个人修为、灵根或突破成功率。

## 2. 核心循环

点击取得灵气 → 聚灵阵生产 → 凝气成石 → 茅屋与弟子 → 职位及原料产业 → 修真和技艺 → 加工、建设、扩仓 → 破境 → 转世／飞升。

开局没有资源、弟子或建筑。第一座聚灵阵需灵气12，第一间茅屋需灵气40与灵石1。手动凝气成石用灵气45换基础灵石1。

## 3. 资源系统

共24种资源。灵气、灵木、玄铁、灵草、感悟和香火支撑生产与经营，加工品连接建设及破境，正负灵子与灵能构成后期产线。仙缘和道果是永久成长记录，不走常规每秒生产。

### 3.1 数量与价格

标记 integer 的资源整件计数：费用向上取整、库存与奖励按相应规则取整。制作收益的小数累计在 craftProgress，累计足一件才入库。资源增加受实际容量限制，旧档或拆仓后超额库存允许消费，不能继续增长。

### 3.2 仓储上限模型

上限 =（基础容量 + 专属扩仓 + 通用扩仓 × 该资源 storageWeight）× 仙缘仓储倍率；整件资源最后向下取整。基础物资、普通成品、进阶成品采用不同权重；专属仓储全额计入。完整权重和容量见数据表。

谷仓、库房、材料库、药藏、法藏、洞天和通天塔构成扩仓链。建筑的 storage、storageAll、maxDisciples 按已建数量生效，停用或缺料不移除这些容量／人口效果；生产、加工增益及带维护费建筑的士气、防灾等运行效果按有效供给生效。

### 3.3 灵气与点击

灵气同时用于弟子口粮、凝石、加工与设施维护。点击收益不乘全局产出倍率：2.5 + 0.5 × 有效聚灵阵数；前20座全额计入，超过20的部分按 √(超出数量) 折算。

### 3.4 渐进露出

建筑已建过则持续显示；未建时需满足全部 needs，并让各项造价资源的历史峰值达到基础成本的 unlockRatio（默认30%）。部分建设目标设为0，前置满足即显示。花光库存不抹去峰值。

## 4. 弟子、职位与士气

有空房时默认每15秒来一名弟子，到来间隔 = 15 ×（1 − min(0.8, arrivalBonus)）。满员时停止并清空到来计时。

六种职位为阵徒、樵夫、矿工、采药人、悟道者、香使；分配人数不得超过总人口，闲置弟子也消耗口粮。每名弟子基础消耗为0.25 × 当前境界倍率灵气／秒，减耗最多85%。

矿工每人每秒基础产出0.08玄铁；建成且启用灵石矿时，另产0.0008灵石，为玄铁基础产出的1/100。副产出使用矿工职位加成与灵石资源倍率，记入资源来源明细；多座灵石矿不重复放大人力，停用后副产出停止。

士气 = clamp(100 + 士气加成 + 断供惩罚, 15, 200)，以士气／100进入全局产出。断供惩罚按6／秒增加，正常供给按2／秒恢复，惩罚下限−60。长期断粮会独立触发流失，不会被高舒适度抵消；低于45%士气也会触发流失，计时间隔25秒。

## 5. 建筑系统

共8组37种建筑，价格按现有数量指数递增。连续购买从现有数量开始逐座累计造价，整件材料按价格函数取整。拆除返还被拆数量对应原购价的一半，实际入库仍受容量约束。

### 5.1 效果字段语义

| 字段 | 用途 |
| --- | --- |
| prod | 每秒基础产出 |
| ratio / jobRatio | 对应资源普通生产／岗位增产 |
| craftBonus / craftBonusByResource | 通用／专业制作收益 |
| storage / storageAll / maxDisciples | 专属容量／按权重折算容量／人口容量 |
| morale / disasterGuard / consumeRatio | 士气／防灾／弟子减耗 |
| autoCraft / autoCondense | 常驻自动加工／节气满仓凝石 |
| offlineHours / arrivalBonus / breakthroughDiscount | 离线上限／招募加速／破境减费 |
| ascendBonus / karmaRatio | 仙缘结算收益／仙缘产出乘区固定附加值 |

建筑、技艺与法宝的永久产业增益按资源区分，当前条目不提供 ratioAll；成就全局奖励当前也为0。引擎仍保留该字段的处理能力。

### 5.2 维护费与停用

带 upkeep 的设施可以停用。有效运行数量为已建数量 × 启用状态 × 供给比例，维护费与运行收益同步缩放；缺料按供给运行而非负库存借贷。容量与人口效果按3.2节处理。

## 6. 修真与技艺·法宝

39项修真、29项技艺、16件法宝，共84项。共享感悟与已学记录；building、buildings、upgrade、upgrades、realm 前置共同生效，允许跨层引用。

修真主要开放建筑、系统与后续条目；技艺提供原料产业、制作、容量等专门收益；法宝可以反复祭炼。界面五段为感知、识物、造物、制度、法则，是主题分类，不是五段必须顺序完成的进度。

法宝基础效果在炼成时生效，n级祭炼效果为基础 ×（1 + 0.3n）。下一次费用的非感悟部分沿用炼成材料 ×1.7^当前等级；感悟用 refine.insight ×1.7^当前等级。部分法宝到指定等级另加进阶材料，从该等级起按1.7倍增长，无等级硬上限。

全部节点及实际前置疑点见修真审视文档。

## 7. 制作

13个配方。每份收益 = amount ×（1 + craftBonus + craftBonusByResource[out]）；普通生产倍率不直接提高配方收益。制作增产相加，没有统一上限。手动制作瞬时完成，自动加工的间隔为配方 time ÷ max(1, √(境界倍率／2))。

木作器械开放木板；金丹的阵基装配、淬玄工艺、凝晶工艺分别开放阵基、玄钢、灵晶。丹药、符箓、法器通过专业建筑开放，其余高级配方使用设施、法宝或研究前置，并不统一按境界分层。

凝灵诀在每个节气检查满仓灵气，尝试用半仓凝石；心有灵犀开放常驻自动加工；首颗道果永久开放自动、单个优先配方及材料保留。凝灵诀或常驻自动入口均开放库存目标，0表示不限，消费后补货。

各配方独立计时；常规按数据顺序处理，材料不足或成品满仓暂停，最多保留一份加工时间。道果优先设置只把指定配方排在前面，不提供共享工位。百工坊每座通用制作+6%；专业设施按成品分别加成。

## 8. 境界与飞升

### 8.1 境界

凡体 → 引气入体 → 炼气 → 筑基 → 金丹 → 元婴 → 化神 → 炼虚 → 合体 → 大乘 → 渡劫。全局倍率依次为1、1.15、1.35、1.6、2、3、5、8、14、24、40。

破境只检查下一境费用，足额支付后必定成功。破境心法、候时法、心印法的折扣相加为40%；引擎折扣上限90%。当前没有渡劫战斗或必须完成指定研究的突破条件。

### 8.2 飞升

渡劫可以飞升，获得仙缘及1颗道果；不要求先转世或学完科技树。资源、人口、建筑、修真、技艺、法宝及祭炼、境界、加工进度、临时增益与事务状态重置。

### 8.3 转世

化神起可转世，只结算仙缘，重置范围与飞升相同。永久仙缘、道果、成就、长期统计与相关偏好保留。

### 8.4 道果与仙缘

仙缘结算 = floor(√(本世累计入库感悟／2000) ×（1 + 境界下标×0.3）×（1 + ascendBonus）×（1 + 道果数×0.1）)，可结算时至少1点。已花感悟仍计入，满仓被截断的部分不计入。

每点仙缘带来+2%产出与+0.15%仓储，分别通过 softCap 渐近+200%与+50%；前75%上限线性，之后收益递减。每颗道果提供+5%产出与+10%仙缘结算收益，首颗同时提供自动化规则。

因果通感另向仙缘产出乘区固定加0.005，不按仙缘点数放大；其仙缘结算加成为30%。

## 9. 成就

25项，记录阈值与行为，转世／飞升保留。ACHIEVEMENT_REWARD 当前为0，无全局产出奖励；后续奖励设计未实施。

## 10. 随机事件

### 10.1 事件等级（v0.10）

34条事件，等级与处理类型分开：一级金丹前，二级金丹至化神，三级炼虚起；单条 minRealm／maxRealm 与等级范围取交集。类型分环境、突发、选择。

### 10.2 触发与结算

初始事件计划在开局90秒后，后续随机间隔150～420秒；选择类共用一个未决状态。限时增减益进入相应乘区；资源机缘、交易和灾损使用产能估价、库存比例、保底或固定材料，交易需足额支付，防灾减免最高80%。

金丹药圃威胁有5分钟处理期，支持加固、驱逐、收缩、默认防守；超时默认结算一次，并进入安宁／冷却。离线不生成新随机事务，已有超时威胁仍处理。现行应对费用与扩展草案见 [MIDGAME-EVENTS.md](MIDGAME-EVENTS.md)。

## 11. 产量公式与时间模型

### 11.1 产量与收支

普通产出 = 基础建筑产出与已含岗位加成的职位产出之和 ×（1 + 资源ratio）×（1 + ratioAll）×（1 + 季节加成）× 全局倍率 ×（1 + 指定资源临时增益）。

全局倍率 = 境界倍率 × 仙缘乘区 × 士气／100 ×（1 + 道果数×0.05）×（1 + 全局临时增益）。当前士气乘区也用于普通建筑产出。

实际结算净额扣弟子口粮和维护费；自动加工逐份扣料，不并入 expense 以免双扣。界面 resourceFlow 另外计入当前运行配方耗料，因此显示净额可以与内部 derived.net 不同。

### 11.2 时间模型

主循环100ms，默认每20秒存档。离线按1秒步长补算，默认最多8小时；龟息功、定息法各增加8小时。超过1秒的 tick 也拆为至多1秒小步。

### 11.3 历法与灵能

一天3秒，节气15天／45秒，季节90天／4.5分钟，一年360天／18分钟。四季产出因资源而异，六种常规资源的全年平均季节增益均在±5%内。

大乘通过阴阳分灵→湮灭法开放灵能产线。灵能每秒乘0.995，增益 = softCap(库存×0.02, 5)，渐近+500%，并非250库存时硬封顶。此增益只写入指定基础资源的普通生产ratio；木板和凝气成石配方收益不直接受益。稳态需按实际炉产出、全局倍率及供料估算，不能把每炉基础0.06／秒直接当作最终产出。

## 13. 存档设计

localStorage 键 slack-off-sect.save.v1，存档结构版本1，与游戏v0.14版本号分别维护。状态包含资源、峰值、人口与岗位、建筑、已学条目、成就、祭炼、自动加工计时与目标、境界、仙缘、道果、历法、事务、统计及偏好；derived 重算，不保存。

序列化排除 __ 开头内存字段，纪事只保存最近60条。导出为base64编码的JSON，也接受原始JSON导入；normalizeState补齐缺失字段并归一化。新字段兼容及非法输入边界由测试验证，不承诺任意未来规则都无需迁移。

存档按浏览器同源隔离，协议、域名或端口改变会使用不同存储；同源下仅改变路径仍访问同一localStorage。清除浏览器数据会删除存档，设置页提供导出备份。
