# 基础生产设施的灵能改造

更新：2026-10-25，v0.425。五类灵能阶段已实施，长期回本待验证。完整首价、涨价率及前置查[生成表](TABLES.md)，阶段定义见[源码](../src/data/productionStages.js)。

## 1. 参考与范围

本地猫国[建筑源码](../cat-zh-master/js/buildings.js)采用分阶段建筑，切换时清零该类数量，再按新阶段建设。猫国部分变体是能源生产设施；本作按用户要求将本轮高阶生产设施设为持续消耗灵能的选择。

只覆盖伐木场、采矿场、炼铁炉、灵石矿、药圃，每类同一ID、同一套数量和基础／灵能两个阶段。地面仍50类建筑，另列5种变体。聚灵阵及聚灵大阵保留原有引气／恢复职责；分灵、偏极、湮灭、聚仙继续沿用原能源链。

## 2. 资格与改造操作

炼虚掌握灵能输配后，可手动取得新资格 `poweredProduction` 灵能营造；各类还需满足自身专业知识。资格不附赠增产或建筑。

1. 主动改造时，本类数量清零、不返材料，切到高阶并默认停用。预览明确旧数量损失、高阶首价、维护和能力变化。
2. 玩家按高阶造价手动重建、手动启用。首座不要求仍拥有被清空的基础建筑；价格指数从该阶段数量重新计算。
3. 可主动退回基础，同样清零、不退款，再按基础造价重建。关闭或缺能只停止／降低运行，不自动降级。
4. 切换原子处理数量、阶段、启停和注灵设置；高阶0座也能保存读档。

清零只在玩家主动切换时发生。普通更新不删除基础设施，旧档无阶段字段时按基础阶段保留数量。

## 3. 五种高阶能力

下表为每座满供、未叠其他增益的基础量；资源比例叠入既有加成层，不是最终产量独立倍数。

| 基础→高阶 | 高阶能力 | 每座灵能／秒 | 专业条件 |
| --- | --- | ---: | --- |
| 伐木场→灵锯采木场 | 灵木持续产出比例+30%，基础为+10% | 0.002 | 灵纹锯阵 |
| 采矿场→灵钻矿场 | 矿石比例+35%、玄铁和灵石各+10%，基础三项均+10% | 0.003 | 矿脉通灵 |
| 炼铁炉→灵能冶铁炉 | 基础产玄铁0.45／秒、耗矿石0.6／秒，不再烧灵木 | 0.008 | 灵火冶炼 |
| 灵石矿→灵脉采掘井 | 每座给每名有效矿工提供天然灵石基础副产0.0045／秒 | 0.004 | 注灵原理、秘银提炼 |
| 药圃→灵能药圃 | 灵草比例+30%；每3座满供提供2单位基础育草容量，基础为1 | 0.003 | 百草育灵 |

五类各一座满供合计0.020灵能／秒，即72／小时。裸基础账中，一座湮灭炉毛产0.06／秒、自用0.015／秒，净额0.045／秒；五座用掉其约44.4%，尚未计其他设备、加工、逸散与小界，不能据此承诺一炉足供实际宗门。

## 4. 实际供给与停止规则

- 伐木、采矿、药圃的设施比例按启用数量及实际供给缩放。断能不保留基础形态的+10%，岗位自身生产仍按原条件运行。
- 冶铁同时支付矿石和灵能，按可支付比例出铁。矿工手工玄铁副产独立存在；炉子不直接产玄钢，也不增加炼器工位。
- 采掘井必须有有效矿工；无人时不产天然灵石、不收该井用能。高阶不收旧灵液注灵、不叠其翻倍，退回基础后注灵默认关闭。
- 育草容量按有效供给计算，与草脉温养、百工传承的容量比例同层处理；仙草配方仍真实支付原料。无人采药不等于育草无工作，不能据此免维护。
- 除采掘井人手条件外，没有新增满仓／无需求自动停机；启用但闲置仍可能收维护，玩家可手动停用。

维护不因祭炼、宜居或资源倍率自动再次提高。产物、原料和维护各按现有结算层计算，不新增重复放大的吞吐倍率。

世界、法宝、工位与高阶设施共用真实能源预算，不能重复消费库存，不能用未供能的副产反向证明能源充足。在线／离线均用有界结算；断供不毁建筑，玩家可退回基础恢复经营。

## 5. 与其他投资的分工

旧 `energyDrive` 灵能引采已删除，无维护的五类原料+25%不再保留。新资格、逐座建设和持续用能共同承担扩产成本；基础路线仍可选，不要求五类全部改造才能普通飞升。

灵火冶炼改善玄钢／器物加工，高阶炉改善玄铁供给；高阶药圃提供育草基础容量，草脉温养与百工传承提供容量比例。不同输入、产物和工位分别核算。

永久商品灵枢调校已实施，仅减这五类高阶设施维护，满级10%。小界协灵阵只影响指定四类居住设施，藏灵只减自然逸散，三者不能混成全局节能。

## 6. 报价、界面与兼容

当前阶段的名称、造价、涨价率、效果、维护、副产及育草容量由 `buildingMeta` 统一解析，建筑动作、展示和模拟共用。建设与拆除使用当前阶段、当前有效价格；改造／回退不走拆除退款。

建筑卡沿用生产分类，区分阶段、改造、启停和维护。完整机会成本、缺料解释及回本提示可按长测发现继续改善，设计期页面设想不等于已验证界面。

旧档按[工程约定](ENGINEERING.md#后续内容重构的旧档策略)处理：基础数量与合法库存数字保留，旧ID及悬空设置清理，新资格未学。已有高阶的新存档保留阶段、数量和启停，重复读档不清零。正常轮回清本世设施与研究，恢复基础阶段，不自动升级重建。
