# 引擎冒烟测试

日常运行 `npm run smoke`，只执行开局、建造、收支、自动加工、手动制作、研究与飞升、存档及金额域共8组核心检查，执行进程限时5秒。`npm run smoke:full` 才执行完整清单及架构回归，包含12小时机器人、稳态和离线模拟。

局部改动用 `npm run smoke -- --group=saveSerialization` 选择一个功能组；`npm run smoke -- --list` 列出名称，`--group=architecture` 单独检查架构。未知名称和不支持的参数直接报错。输出各组实际耗时，便于识别新加入的慢测试。

## 组织方式

- `../smoke.mjs`：选择运行范围、执行清单和汇总耗时／结果。
- `checks.mjs`：保留完整清单及顺序，另列日常核心检查。
- `../lib/checks.mjs`：每次运行独立的 `ok`、`close`、`section` 和统计汇总。
- `fixtures.mjs`：新档、已开山存档和强制成功突破的公共夹具。
- 其余文件：按功能维护操作闭环和必要边界。开局在 `startup`，数据契约在 `catalog`；专项边界和迁移回归由完整清单或功能组按需运行。
- `extensions.mjs`：连接已有的工业、弟子和离线专项检查，不复制其实现。

## 新增用例

1. 在对应功能文件中导出一个测试函数，按需接收 `{ ok, close, section }`；异步检查使用 `async` 函数。
2. 在 `checks.mjs` 的完整清单登记该函数。只有通用、快速的核心闭环才加入默认清单，长模拟与专项矩阵留在完整清单。
3. 用例自行创建状态，需要公共场景时引用 `fixtures.mjs`；不要依赖其他用例留下的状态，也不要在模块导入时执行测试。
4. 只运行 `npm run smoke -- --group=<函数名>`，确认断言汇总和退出码；调整默认清单时再跑日常检查。不因局部修复重复运行完整回归、产业、记录恢复和小数专项的全部用例。

`../industry-check.mjs`、`../disciple-check.mjs`、`../offline-check.mjs` 等专项工具继续复用。新用例放入对应功能文件，不再向入口或清单中堆入测试主体。
