# 妖兽猎杀与兽材利用

更新：2026-10-19。**首轮山麓闭环已实现；2026-10-19 起改为即时猎杀：只选择有加成的弟子，普通弟子自动补足至多5人，立即结算且不占岗位，自动重复按30～3600秒间隔执行；旧 v1/v2 已付款任务在正式加载／首次推进前按原快照与有效仓容结算一次。深山与禁地、生态关联及部分技艺仍为待实现方案，交付计划见 §11。** 本文是工作草案，产量、门槛、间隔和技艺数值均需实测。当前数据见 [TABLES.md](TABLES.md)，通用规则见 [DESIGN.md](DESIGN.md)。

猎杀实现位于 `src/modules/hunting/`，通过游戏模块注册表与界面注册表接入。即时猎杀不占用成员、不清空岗位；关闭模块停止新猎杀并结算旧档已付款任务，外交仍启用时保留共享执符使岗位及信符供给。读档保留历史统计、兽材小数余量、随机序列、名单、间隔与已消耗进度；旧 v1/v2 活动任务按原快照结算一次，反复读档不重复发奖。

## 1. 目标与范围

核心循环：执符使准备信符 → 玩家选择猎场与 1～5 名弟子 → 立即消耗信符结算兽材 → 用于起居、炼器与防护。

用户已确定的方向：玩家明确选择猎场与 1～5 名弟子，点击后立即结算；参与猎杀不占岗位、不停止生产。推荐阵容按真实期望贡献排序，但只有玩家点击才替换名单；不再有“钉选必入/闲散优先”的自动分层。回报同时考虑个人与宗门境界；高级妖兽提供高级材料；猎杀技艺改善成功率、收获和信符消耗；预留与妖兽来袭的关联。每队最多 5 人、基础信符仓容 100、每座执符堂增加 300 为当前规则。

捕猎本身不直接增加永久宜居度，材料用于保暖、陈设和法宝后才兑现效果。首期不加入装备槽与逐只战斗，也不把猎杀列为突破的必修路线。**伤亡情况（弟子受伤／身死及其后果）已登记为后续待策划项，本次不设计、不实现。**

```mermaid

    A[执符使准备信符] --> B[选择猎场 · 自动组队]
    B --> C[消耗100信符出征]
    C --> D[兽皮：起居与护具]
    C --> E[兽骨：法器与灵器]
    C --> F[高阶兽材：防护与灵符]
    C -. 活动与清剿记录 .-> G[猎场警戒与威胁抑制]
    G -. 后续启用 .-> H[妖兽来袭事件池]
```

## 3. 后勤、即时猎杀与自动周期

### 3.1 执符使与信符

信符是宗门共享资源，库存、仓容与开具净速率显示在左侧“修行资源”分组，猎杀页不再重复展示开具面板；每趟出征仍消耗 100，邻宗互市每回消耗 50。

执符使 `huntPlanner` 在启用中的执符堂准备，不直接产出兽材。基础速度暂定 0.20 信符/秒·人，沿用普通岗位规则：

```text
P = 0.20 × Σ REALMS[min(个人境界, 宗门境界)].mult
         × 宗门境界倍率 × 其他适用岗位和生产倍率
准备等待 = max(0, 100 - 库存) / P
```

P 为当前留在执符堂、没有出征的执符使总准备速度；P=0 时显示无准备来源。个人与宗门倍率只在普通岗位公式中各计一次，点数和准备速度不再乘进出征奖励。

不计其他加成时，1 名凡体弟子在筑基宗门为 0.32 点/秒，约 313 秒准备一次；筑基弟子为 0.512 点/秒，约 195 秒；元婴弟子在元婴宗门为 1.352 点/秒，约 74 秒。

初始库存 0，每次只扣 100；250 点出发后剩 150。达到 100 只是允许出发，不强制启动任务。基础仓容 100，每座执符堂增加 300；开具到达实际上限后停止积累，不能越仓或换成奖励。阈值判断使用真实库存与现有金额比较助手（Decimal 精确比较），不用显示取整后的值判断，也不放宽为模糊容差。

### 3.2 一次出征的生命周期

1. **选择加成**：玩家指定猎场，页面只列出有猎杀天赋的合格弟子供勾选，显示本人实际成功率、收获倍率及同阵容天赋额外收益。所选加成弟子优先，普通弟子按真实期望贡献自动补足至多5人；未勾选的加成弟子不参与。没有加成弟子也可由普通弟子猎杀。检查研究、设施、宗门境界、实际队伍与信符。
2. **立即结算**：一次点击原子完成资格校验、扣信符、逐人判定、掉落入库、小数余量与统计更新；不创建任务、不写 onMission、不清空 roleId、不改变岗位人数或生产。
3. **自动重复**：默认关闭；开启后每隔 30～3600 秒（默认 60）尝试一次，每周期最多一次。开启或改间隔从 0 计时；手动成功也重置计时。失败周期跳过，不累积欠账；关闭模块清零。
4. **旧档迁移**：旧 v1/v2 已付款在途任务在正式加载或首次推进前按原快照结算一次，按有效仓容入库，恢复原岗位、清除任务并重算后再开始生产；关闭模块也走相同迁移，归一化不结算。v1 按旧120秒与旧基准收益，v2 按原60秒与个人倍率。反复读档不重复发奖。
5. **配额**：每次仍扣 100 信符的猎杀专属折后价（《踏山步》−10%，向上取整且至少 1）；信符不足或名单无效时不扣费、不消耗随机数、不发奖励。

即时猎杀不占用成员，也不另建持续生产兽材的岗位。普通补位统一按 A×y×(p+0.2(1-p)) 降序、同分按ID升序，不区分闲散和在岗。勾选的加成弟子保留玩家指定优先级，普通成员不需要逐人管理。

猎场、成员身份、宗门及有效个人境界、成功率、收获倍率与基础掉落表在本次点击时确定；自动周期使用相同的加成人选与普通补位规则，不擅自选入未勾选的猎杀天赋弟子。调间隔只改变执行频率，不改变单次奖励。

所有该猎场产物都已达到库存目标或满仓时，即时结算仍按现有入库上限处理并显示溢出；自动周期继续尝试，不建立无限待领取仓库。飞升或转世清空本世猎杀配置与信符，不能重置后领取旧任务收益。

### 3.3 长期供给与离线

加成人选与普通补位结果不变、自动重复开启且信符有缓冲时：

```text
自动执行间隔 = max(30, min(3600, autoIntervalSeconds))   // 默认 60 秒
可持续次数 ≈ 信符净产 / 单次折后信符费
材料平均秒产 ≈ 单次期望回报 / 自动执行间隔
```

自动频率受信符准备速度、名单资格和单次费用共同约束；调短间隔不会改变单次奖励，只会更快消耗信符。信符不足或名单失效时跳过该周期，不形成欠账。

离线按周期数批量估算：先结算旧 v1/v2 已付款任务（一次、原快照），再按 `floor((elapsed + dt) / interval)` 计算可执行周期，并同时受实际信符存量、名单资格和 `canDepart` 封顶；奖励用当段名单的成功率期望，掉落保留小数余量，不逐秒/逐次循环，不生成尾段任务，不把跳过次数带回在线。最后只保留不足一周期的进度。长离线结果可能与在线逐趟不同（见 [ENGINEERING.md](ENGINEERING.md#离线结算)）。

## 4. 成功率、材料等级与收益公式

以下所有参数均为试调值。每名弟子分别计算再相加，不使用平均境界，也不让强者的境界代替全队。

```text
e_i = min(个人境界 r_i, 出发时宗门境界 S)
A_i = 2 ^ clamp((e_i - D_h) / 2, -2, 1)
C_h = 1 + 0.10 × clamp(S - U_h, 0, 4)
p_i = clamp(p_base,h + 0.06 × (e_i - D_h)
                     + 0.02 × clamp(S - U_h, 0, 3)
                     + Σ huntSuccessBonus
                     + 天赋猎杀准头(huntSuccess), 0.35, 0.99)
y_i = 1 + 天赋猎杀收获(huntYield)
```

A 是个人效率，范围 0.25～2；匹配推荐境界为 1，低两阶为 0.5，高两阶为 2。C 是宗门支援，最高 1.4。基础成功率 p_base 分别为山麓 0.90、深山 0.80、禁地 0.70；每名弟子每次只判定一次，其全部材料共用结果。独立随机序列用于猎杀，预览不消耗随机数，读档不重抽已结算结果。

**个人猎杀天赋（v0.421，天地玄黄四档 × Lv.1–3）**：「猎杀·准头」（huntSuccess）按百分点加本人成功率，黄级 Lv.1 +2pt 至天级 Lv.3 +14pt，上限 +14pt（口径同突破天赋）；「猎杀·收获」（huntYield）按比例加本人收获倍率 y，黄级 Lv.1 +10% 至天级 Lv.3 +90%，上限 +90%（口径同修炼/岗位天赋）。两条只作用于持有人本人，与宗门级的 huntSuccessBonus／huntYieldBonus 技艺独立叠加；出生随机与突破获取的规则同其他天赋类别（见 [DISCIPLE-TALENTS.md](DISCIPLE-TALENTS.md)）。

山麓进阶占比 q=0；深山、禁地为：

```text
q_i = clamp(0.20 + 0.20 × (e_i - R_h)
                  + 0.05 × clamp(S - U_h, 0, 2), 0, 0.90)
```

q 是贡献分配到进阶档的比例，p 是猎杀成功率，两者独立。高境界可同时提高效率、成功率与进阶占比，但不突破猎场材料上限。由于更多贡献转向高级材料，同一猎场的普通档产量不保证随境界单调增加。

| 材料档位 | 分配系数 w | 成功系数 Z | 预览期望 E[Z] |
| --- | --- | --- | --- |
| 山麓基础档 | 1 | 成功 1，失败 0.20 | p + 0.20×(1-p) |
| 深山 / 禁地普通档 | 1-q | 成功 1，失败 0.20 | p + 0.20×(1-p) |
| 深山 / 禁地进阶档 | q | 成功 1，失败 0 | p |

失败的普通档是沿途采集保底，不猎获目标的高阶特产；仍消耗时间和信符。每人分别判定，队伍显示预计成功人数 Σp，不把它叫作整队成功概率。小数保底可能暂未凑成整数，界面显示累计进度，不能承诺每次都有整数材料到账。

| 猎场 | 普通档基准秒产 b | 进阶档基准秒产 b |
| --- | --- | --- |
| 山麓 | 兽皮 0.24、兽骨 0.16（v0.421 随时长减半翻倍，单次收益口径不变） | 无 |
| 深山 | 兽皮 0.03、兽骨 0.02（方案值） | 玄纹骨 0.03、灵韧皮 0.04 |
| 禁地 | 玄纹骨 0.015、灵韧皮 0.02（方案值） | 兽魂晶 0.005 |

同档内骨皮同时产生，两档通过 q 分配贡献。最终每种材料为：

```text
H(t) = 1 + min(1.00, Σ huntYieldBonus(t))
G_m(t) = H(t) × 其他适用的非境界倍率
平均增益 Ḡ_m = ∫[0,T_actual] G_m(t) dt / T_actual
Y_h,m = b_h,m × T_base × C_h × Σ(A_i × y_i × w_i,m × Z_i,m) × Ḡ_m
```

y_i 是个人猎杀收获天赋倍率（无天赋为 1），只乘持有人的贡献，不整队放大。

其他倍率包括适用的宜居、仙缘、道果、资源及临时增益，每项只计一次。猎杀收获技艺和法宝统一进入 H，不在其他倍率里重复叠加；不直接乘含境界的 `derived.globalMult` 或 `discipleFactor`，也不套制作增产。灵根只影响弟子自身修炼与个人突破成功率，不进入本公式。

缩时后仍用 T_base 计算单次基础回报，实际时长只用于平均增益与任务完成时间。180 秒任务若催猎覆盖 30 秒、期间 +50%，其平均增益为 (150+30×1.5)/180，整次增产 8.33%；不能在返回前点击后追溯整次 +50%。

## 5. 修真研究与强化技艺

修真研究负责猎场和工艺解锁，技艺负责数值强化；强化支线不全部成为进入猎场的必修前置。入口只用原资源或前阶材料，进阶技艺可消费本猎场已能取得的材料。

| 技艺 | 建议前置 | 试调效果 | 投入方向 |
| --- | --- | --- | --- |
| 识踪诀 | 山野猎法 | 成功率 +5 个百分点 | 灵机、灵木、灵石 |
| 剥取法 | 兽材加工 | 收获 +15% | 灵机、普通骨皮 |
| 踏山步 | 山野猎法 | 信符消耗 −10% | 灵机、灵石 |
| 筹猎章 | 山野猎法 | 执符使准备速度 +25% | 灵机、灵木 |
| 破妖诀 | 深山猎法、识踪诀 | 成功率 +8 个百分点 | 灵机、玄纹骨、灵液 |
| 取髓诀 | 深山猎法、剥取法 | 收获 +20% | 灵机、玄纹骨、灵韧皮 |
| 缩地行 | 深山猎法、踏山步 | 信符消耗 −15%（后续） | 灵机、灵液、玄钢 |
| 镇魄诀 | 禁地讨妖、破妖诀 | 成功率 +8 个百分点 | 灵机、兽魂晶 |
| 敛息法 | 深山猎法，生态关联已启用 | 警戒增量 −20% | 灵机、灵韧皮、灵符 |

```text
信符费用 = max(1, ceil(100 × (1 − min(0.90, Σ huntCostReduction))))
```

成功率最高 99%，收获技艺与法宝合计最多 +100%，信符减耗最多 90% 且只作用于猎杀，不影响外交。成功率增量按百分点显示，其他按比例显示，使用独立效果字段；筹猎章用 `jobRatio.huntPlanner`。警戒减免也单独配置并限制在 0～80%，只减少新增警戒，不清除旧警戒；未启用生态关联时不开放敛息法。

单次基础回报固定为山麓兽皮 14.4、兽骨 9.6 的基准展开，不再按秒产×时长计算。自动间隔只改变执行频率，不改变单次奖励；信符准备速度决定可持续的自动频率。

## 6. 兽材的生活、炼器与防护用途

### 6.1 宜居度

**暖裘居室**是保暖陈设配套，不增加住额。筑基、山野猎法、木屋至少 1 座后开放；首轮造价灵木 300、矿石 100、兽皮 40、兽骨 20，按 1.35 倍涨价。每座宜居度 +4、兽皮维护 0.10/秒，停用不消耗也不生效，缺料按供给缩放。

匹配山麓推荐境界、宗门刚到入口的单人任务，成功回报 14.4 兽皮，90% 成功率加失败保底后期望 13.248（v0.421 单次收益口径不变）。连续 60 秒一趟（需信符备速 ≥1.667/秒）时等效 0.2208/秒；若后勤使间隔变为 200 秒，则只有 0.06624/秒，供不起单座居室。多人贡献与准备人力必须一起计入成本。

60 秒正常维护消耗 6 兽皮，还需额外储备等待和连续失败缓冲。上例（信符不设限的连续运转）单座长期净余 0.1208/秒，攒第二座所需 54 兽皮的期望约为 7.5 分钟；但该口径要求备速 ≥1.667/秒（约 5.2 名凡体执符使），后勤受限时按实际间隔折算。这是试算，不保证不断供。现有清风小院、膳养堂等永久设施继续作为基础选择。

**御寒灵裘**是可祭炼的生活法宝：金丹、兽材加工、炼器坊后开放；首轮费用兽皮 120、兽骨 80、法器 2、灵石 60，基础宜居度 +6。进阶祭炼仍消耗兽材，费用增长需避免轻易替代持续供给线。深山阶段可用玄纹骨与灵韧皮进一步祭炼，提供当期高级材料去向。

## 7. 来袭关联与持久状态契约

新系统首轮预留结构，关联系数可先关闭。成功清剿产生短期威胁抑制，出征活动、惊扰和失手可能增加警戒；两者分开，不把一次出征硬绑定成一次袭击。妖兽事务继续使用 [MIDGAME-EVENTS.md](MIDGAME-EVENTS.md) 的事件与期限规则。

```js
state.hunting = {
  schemaVersion: 3,           // v3：即时猎杀、周期执行；兼容v1/v2已付款任务
  nextMissionId: 1,
  randomSeed: 1,              // 新游戏初始化独立种子，存读档不重置
  missions: {},               // 只用于旧档待迁移快照，新猎杀不创建任务
  yieldRemainders: {},        // 各兽材小数累计，范围 [0, 1)
  fieldState: {},
  lastOutcome: null,          // 最近任务的结算或取消记录，不无限保存历史
  statistics: { departures: 0, completedMissions: 0, cancelledMissions: 0,
                successfulHunters: 0, failedHunters: 0 },
  settings: { selectedFieldId: null, teamIds: [], autoRepeat: false,
              autoIntervalSeconds: 60, elapsedSeconds: 0 },
  // teamIds 保存所选加成弟子，普通弟子由resolveHuntTeam自动补足
}
```

信符只存在 `resources.warrant`，与宗门外交共用；旧档 `huntPreparation` 已迁移到该字段，不保留第二份库存。成员身份与当前成长以弟子表为权威；任务保存成员ID、原岗位与必要的数值快照，不复制一套可独立成长的弟子对象。

活动任务至少保存：`id`、`fieldId`、`status`、`startedAt`、`progressSeconds`、`baseDuration`、`actualDuration`、`formulaVersion`、掉落表快照、各成员有效境界／效率／占比／成功率／个人收获倍率快照、`gainIntegrals` 和 `preparationPaid`。成员有可校验的任务占用标记，岗位统计只计算未出征成员。状态为执行、已结算或已取消；支付、成员锁定与结算均原子完成，保存不得出现半结算状态。

已结束任务移出活动表，只保留有限结算摘要；重复结算请求必须匹配当前活动任务且尚未结算。小数累计跨任务保留，整数入库后只保留不足 1 的余量；超仓整份显示为溢出，不留作下一次领取。取消不改变过去已经累计的小数。读档校验任务ID、成员唯一性、猎场ID、数值范围和关联一致性。合法 v1 山麓在途任务保留原 120 秒基准时长、已完成进度、旧秒产（兽皮 0.12／兽骨 0.08）及岗位快照，个人收获倍率按 1；连续读档仍按旧规则完成当前趟，归队恢复岗位且不重复收费，新出征再用 v2。损坏或未知版本任务不作为合法 v1 迁移。

每个 `fieldState[fieldId]`：

```js
{
  lastUpdatedAt: 0, lastHuntAt: 0,
  completedMissions: 0, successfulHunters: 0, failedHunters: 0,
  suppression: 0,             // 0～100，清剿抑制
  alertness: 0,               // 0～100，活动警戒
  peaceUntil: 0, raidCooldownUntil: 0, lastRaidAt: 0,
  lastSourceMissionId: null,
}
```

两项指标按模拟时钟分别衰减。预留 `applyHuntDeparture` 和 `applyHuntOutcome` 接口：出发记录活动及对应警戒，归队再记录成功清剿与失手影响；取消不退回已产生的活动警戒。每个任务每阶段只更新一次，系数关闭时仅记统计，不偷偷改变来袭率。

猎场配置预留 `raidProfileId`、`ecology`；事件和待决事务上下文预留 `{fieldId, sourceMissionId, cause, threatTier}`，用于解释来源、按猎场提供应对及归还安宁期。历史没有来源字段的事务按原规则处理。

```text
eligible = 阶段允许 && 无冲突待决事务 && 不在安宁期或冷却中
weight = baseWeight × clamp(1 + α×alertness/100 - β×suppression/100, 0.25, 2)
```

α、β 待测，不合格时权重为 0。权重参与事件池归一化，不是独立来袭概率；多个猎场共用同一模板时，先分摊该模板基础权重，不能仅因新增猎场就倍增事件权重。保留现有金丹至化神事务的阶段范围，禁地来袭另设高阶模板。

接口边界：

- 不覆盖待决事务，不重置现有冷却，不连续强塞来袭；来袭不重抽已结算的猎杀收益。
- 处理来袭可改变安宁或警戒，不免费补信符、不重复发整次猎杀材料。
- 离线衰减生态、结算猎杀和已有威胁，仍不新抽事件；更换猎场、退境和停用设施不清空生态。
- 地区化后保留原 `affairs` 安宁与冷却，关联猎场使用地区与全局有效保护期的较晚值；不能迁移后丢失旧保护。
- 状态进入存档白名单，按版本迁移和校验，飞升／转世重置本世状态。未实现时不向现有存档写入假任务或未启用生态。

## 8. 存档兼容

旧兽系存档在未知条目过滤前迁移，`beastRetirementVersion` 防止重复补偿：旧园累计参考建造费用返还 50%，研究、驭兽铃炼成与祭炼参考费用全额返还。超仓材料可保留消费，不赠信符、不自动派人；补偿限制为有限安全数值，迁移不修改输入存档。

## 9. 实施与验收

建议顺序：山麓信符、任务与皮骨生活循环 → 深山兽材和炼器用途 → 禁地魂晶 → 启用生态关联及敛息法。第一阶段即使用稳定猎场ID、任务ID、分阶掉落表和版本化状态。

验收重点：

1. 首座设施可达，没有自身材料前置；试调费用在同阶段现有仓容内可支付。
2. 99 点不能出发，100 扣成 0，250 扣成 150；不重复点击派人或支付，同一成员不同时工作和猎杀。
3. 混合境界逐人计算，猎场限制材料档位；区分成功回报与期望，成功率、收获与缩时上限有效。
4. 缩时不减少单次基础奖励，临时增益只计覆盖时间；小数跨任务累计、超仓不形成无限领奖。
5. 自动重复在人员、门槛、材料目标或后勤不足时等待；取消、拆除、退境、飞升和读档遵守同一生命周期。
6. 同时间线在线与离线一致，存读档不重抽、不重付、不重奖、不重复增加生态。
7. 皮毛断供按负荷降低宜居度；同时检查岗位人力、准备间隔、集中到账与失败缓冲。
8. 替代配方共享成品目标，法宝替代方案不重复获得效果；现有配方与知识门槛保留。
9. 生态衰减、保护期和来袭关联ID可存读，取消不洗警戒、不覆盖待决来袭、不在离线新抽事件。
10. 固定版本、随机源、策略与仙缘，比较不走猎杀、生活猎杀、生活加炼器三条路线：进度、人力、断供时长、满仓比例和单位劳动回报分别报告。

待测参数：队伍与并行规模、信符产速和仓容、各档准入与产量、成功率和保底、技能费用与上限、生活维护、兽材配方价格以及生态增量、衰减和权重。已实现的山麓配置以源码和生成表为准；深山、禁地及生态关联数值仍为方案。

- 资源：玄纹骨 `runedBone`、灵韧皮 `spiritHide`（整数入库、小数累计，仓容并入执符堂定额）。
- 猎场：`deepForest`（元婴入口、弟子筑基起、推荐元婴、180 秒、基础成功率 0.80；普通档兽皮 0.03／兽骨 0.02，进阶档玄纹骨 0.03／灵韧皮 0.04；q 占比公式启用）——引擎结构（`advancedYield`／`advancedRatio`）首轮已预留。
- 研究：《深山猎法》（材料研究·山野组，前置兽材加工＋凝晶原理；费用含灵机与前阶材料，不用自身猎场特产防自锁）。
- 技艺：破妖诀（成功率 +8pt）、取髓诀（收获 +20%）、缩地行（时长 −15%）——费用含深山材料，本身即当期去向。
- 用途：御寒灵裘深山进阶祭炼（元婴）；铭骨铸灵器与安居灵幡兽材方案（化神，替代法器／玄钢投入）——首次出现同成品多配方，需实现「成品共享库存目标」与旧设置迁移（§6.2）。
- 生命周期：自动重复、离线有界快进对深山生效，沿用 §3.2–§3.3 与统一出征条件。
- 验收：§9 全项 + 深山专列——q 分配正确、普通档产量不随境界单调保证、进阶材料开放时至少一种当期消费用途可用。

### 11.4 工作包顺序与依赖

复评包（11.0）可独立先行；深山包（11.1）依赖复评结论（信符后勤与居室供需影响深山的人力预算）；禁地包（11.2）依据深山实玩反馈；生态包（11.3）最后。每包独立交付与验收，不捆绑；成品共享目标机制在 11.1 首次落地，11.2 直接沿用。
