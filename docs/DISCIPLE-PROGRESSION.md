更新：2026-10-12。本文区分当前实现与待设计内容；整理文档不改变游戏规则。弟子成长、灵根和管理已在 v0.32 实施，当前仍沿用首版试调值。整体经营见 [DESIGN.md](DESIGN.md)，工程实现见 [ENGINEERING.md](ENGINEERING.md)，后续方向见 [ROADMAP.md](ROADMAP.md)。

早期草案已移至 [DISCIPLE-PROGRESSION-HISTORY.md](DISCIPLE-PROGRESSION-HISTORY.md)。其中自动晋升、灵根轮盘、旧灵根速度及复杂失败风险不作为当前规则或已批准的开发计划。

## 1. 当前实现

### 1.1 个体与系统边界

弟子拥有持久化身份、姓名、岗位、境界、修为、灵根和调息记录。新弟子从凡体、零修为开始；姓名按身份生成，允许重名，读档不重新生成有效姓名。弟子自动修炼，突破由玩家单人或批量发起。

| 机制 | 当前作用 |
| --- | --- |
| 宗门境界 | 提供现有全局产出及口粮倍率，限制弟子下一次突破的目标境界 |
| 弟子境界 | 提高本人岗位产出系数，同时按相同系数提高个人口粮 |
| 灵根 | 只影响个人修炼速度 |
| 天赋 | 固定个人专长，提供修炼、对应岗位产出或突破加成；随成功突破升至 Lv.1–Lv.3 |
| 培养 | 手动传功：持续耗灵气加速本人修炼（不停岗）；个人护道：预付材料加成其下一次突破 |
| 突破 | 消耗资源并判定成功或失败，不自动使用宗门护道方案 |
| 岗位 | 决定个人提供哪类资源，工作与闲散都继续修炼 |

首版已增加 32 条天地玄黄天赋（含天级岗位词条），获取、效果、固定身份及 Lv.1–Lv.3 升级见 [DISCIPLE-TALENTS.md](DISCIPLE-TALENTS.md)。手动培养（传功／个人护道）见 §2.1。尚无专用培养设施、师承传承、游戏内自动突破、境界停滞或个人突破死亡。

### 1.2 灵根与自动修炼

配置集中在 [src/data/disciples.js](../src/data/disciples.js)。基础速度为每秒 1 点修为，乘以下灵根系数：

| 灵根 | 出现概率 | 修炼速度系数 |
| --- | ---: | ---: |
| 天灵根 | 1% | 2.0 |
| 异灵根 | 4% | 1.6 |
| 双灵根 | 10% | 1.3 |
| 三灵根 | 25% | 1.0 |
| 四灵根 | 30% | 0.9 |
| 五灵根 | 30% | 0.8 |

加权平均速度系数为 0.974。灵根不直接改变岗位产出、口粮、突破成功率或调息时间。

到来或事件招入时只抽取一次灵根，使用存档内独立随机序列；收徒不改变事件及突破的随机序列。已有有效灵根原样保留，旧档缺失或无效灵根补三灵根，读取存档不重新抽取。不使用阻塞式轮盘，在线纪事直接显示收徒结果。

```text
实际修炼速度 = 基础速度 × 灵根系数 × (1 + 个人修炼天赋加成)
修为增长 = 实际修炼速度 × 已结算时间
当前修为最多达到本境突破要求，不预存后续境界的修为
```

工作、闲散及调息期间均继续修炼。达到宗门上限仍可修满本境，但不能突破至宗门境界之上。个人渡劫后不再积累后续突破修为。

离线沿用宗门当前离线收益上限，新招入弟子只计算入门后的时间。读档及后台恢复使用相同逐秒结算规则，加载提示与结算后更新界面的行为见 [ENGINEERING.md](ENGINEERING.md)。

### 1.3 修炼时间与突破概率

下表净修炼时间以无修炼天赋的三灵根为基准，指从上一境开始到修满、可尝试本次突破的时间，不含宗门上限等待、备料和失败重修。天灵根时间减半，五灵根时间增加 25%；修炼天赋另行加速。

| 突破目标 | 本段净修炼时间 | 从凡体累计 | 弟子基础成功率 |
| --- | ---: | ---: | ---: |
| 引气入体 | 1小时 | 1小时 | 47.5% |
| 炼气期 | 3小时 | 4小时 | 47.5% |
| 筑基期 | 8小时 | 12小时 | 47.5% |
| 金丹期 | 16小时 | 28小时 | 35% |
| 元婴期 | 24小时 | 52小时 | 30% |
| 化神期 | 36小时 | 88小时 | 27.5% |
| 炼虚期 | 48小时 | 136小时 | 25% |
| 合体期 | 72小时 | 208小时 | 10% |
| 大乘期 | 96小时 | 304小时 | 7.5% |
| 渡劫期 | 120小时 | 424小时 | 5% |

2026-10-12 调整：弟子基础成功率为对应宗门基础成功率的一半；宗门高于目标时，每高一境增加 10 个百分点成功率，最高 99%。目标高于宗门时不可发起。宗门与弟子共用基础概率入口，宗门护道材料不自动用于弟子。

```text
境界差 = 宗门境界下标 − 弟子突破目标境界下标
弟子基础成功率 = 对应宗门基础成功率 × 50%
成功率 = min(99%, 弟子基础成功率 + max(0, 境界差) × 10% + 个人突破天赋百分点)
```

例如元婴宗门指导弟子结丹，成功率为 45%。灵根当前不额外提高该概率。基础成功率降低后，失败重修及材料消耗的累计成本需重新测量，旧审计不能作为当前培养节奏结论。

### 1.4 材料、失败与批量突破

当前费用由目标宗门境界的基础费用派生，比例单独配置为 1%，尚未建立独立的弟子逐境费用表：

```text
每种突破材料 = max(1, ceil(目标宗门基础费用中该项数量 × 1%))
```

只对目标费用实际包含的资源计价，不套用宗门费用折扣或护道材料。调整宗门基础费用会同时改变弟子费用；是否拆成独立配置属于后续待决定事项。

成功后境界提升一层、修为归零。失败仍消耗全部本次材料，损失 20% 本境修为并调息 60 秒，不降境、不停滞、不死亡。调息期间继续修炼，但不能再次突破。

失败的主要等待成本来自重修损失，而非固定的 60 秒。以三灵根为例，结丹失败需补回约 3.2 小时修为，冲击合体失败约 14.4 小时；重修与调息并行，不能简单相加。

批量突破按个体记录顺序逐人检查、扣料和判定；不满足条件的人选跳过，遇到材料不足则停止，不超支。界面排序不改变实际执行顺序。不同目标境界可同时选中，游戏目前没有自动突破或宗门材料预留策略。

### 1.5 产出、口粮与宗门退境

个人系数复用现有境界倍率，并按有效境界计算：

```text
有效境界 = min(弟子实际境界, 当前宗门境界)
个人系数 = 有效境界对应的境界倍率
岗位实际产出 = 岗位基础产出 × Σ[该岗位弟子个人系数 × (1 + 本人对应岗位天赋加成)] × 现有岗位、资源与全局倍率
全体弟子口粮 = 0.25 × 宗门境界倍率 × Σ(全体弟子个人系数) × (1 − 有效减耗比例)
```

当前口粮随宗门倍率的指数为 1，有效减耗比例上限为 85%。闲散弟子也承担口粮。个人系数只作用于本人岗位产出与口粮，不额外提高每份制作收益、工业容量或建筑自带产出。

宗门与弟子同为金丹时，两层境界乘积为 2×2＝4；同为渡劫时为 10×10＝100。个人境界提高单位人口的产能与口粮，不直接改善该弟子的产出／口粮比。

宗门退境保留弟子实际境界及修为，只暂时降低有效境界系数。宗门恢复后无需重新培养已取得的境界。宗门身死重修、转世或飞升清空个体。

### 1.6 管理、调岗与逐出

弟子页默认展示职位分配；点击“弟子管理”后管理区覆盖职位分配区域，收起或在管理区按 Esc 返回。同页开合保留筛选与选择，重新进入页面默认收起。

- 按境界、灵根组合筛选，按入门先后、本境进度比例、修炼速度稳定排序。
- 每页 30 人，可选择当前筛选内全部人选跨页操作；切换筛选清除选择，排序保留身份选择。
- 支持指定人选单人或批量调岗、突破和逐出，批量操作限于当前筛选内所选人选。
- 列表保留姓名、境界、灵根、岗位、状态及操作；修为、实际速度、预计时间、个人系数、口粮、概率及费用通过悬停行或键盘聚焦姓名查看。
- 缺料与调息状态直接显示。页面统一滚动，筛选在窄屏换行，选择与批量操作独立排列。
- 职位表“每人／秒”显示已分配弟子的平均实际产出，无人岗位显示凡体参考值；口粮摘要显示总量与平均量。

逐出费用逐人向上取整后合计：

```text
单人逐出费用 = ceil(累计灵气消耗 × (在宗门已满游戏年数 + 1))
```

累计消耗包括实际供给的个人口粮及个人突破支付的灵气，停留与消耗在线／离线持续记录。逐出需确认，执行时重新校验人数、费用与支付能力，费用变化或材料不足时整批不执行。成功后移除对应个体、更新人口与岗位，新弟子沿用递增身份，不复用被逐出者的成长记录。

## 2. 后续待设计内容

以下为培养投入与策略的设计与待办，不新增已批准的数值或机制；已设计待实施的条目在文中标注。保持放置经营体验，培养过程尽量自动，玩家决定重点人选与资源投入。

### 2.1 培养投入与个人费用

已实施（2026-10-13）。手动培养分两项，由同一研究解锁，只作用于玩家指定的个别弟子，不改变他人或全宗产出；基础修炼、灵根速度与境界系数仍是基线。数值均为试调，见 [src/data/disciples.js](../src/data/disciples.js) 的 `DISCIPLE_TRAINING` 与 `DISCIPLE_AIDS`。

**解锁**：修真·宗门经营新增《传功授业》，前置《讲经法》与《口传心授》。未掌握时弟子页不显示培养入口；培养不占用建筑或岗位容量。

**传功（持续加速修炼）**

- 在弟子管理页对选中弟子开始或停止传功；弟子照常上岗，口粮与岗位产出不变，只加速本人修炼。
- 效果：个人修炼速度 ×(1 + 传功加成)，与灵根、修炼天赋相乘，加成有上限。

  ```text
  个人修炼速度 = 基础速度 × 灵根系数 × (1 + 修炼天赋) × (1 + 传功加成)
  ```

- 消耗：按弟子有效境界递增的每秒灵气（灵气为主要投入）。
- 停止条件：本境修为已满时该弟子不扣灵气、加成无效，突破后自动恢复；灵气不足时（口粮与维护优先）整批传功暂停、不欠账，恢复后继续。
- 在线与离线同一结算；离线不自动突破，故修为满后离线同样暂停。

**个人护道（突破加成）**

- 为指定弟子的下一次突破预付一组按目标境界配置的材料，个人突破成功率增加固定百分点，手动触发、即时扣料。
- 只作用于本人该次突破，不用于宗门破境或其他弟子；叠加在“弟子基础成功率 + 宗门指导 + 个人天赋”之上，仍受 99% 封顶，不绕过修为、调息、宗门境界与材料条件。
- 成功或失败后清除待生效加成，再次护道须重新支付；同一弟子最多一层。
- 材料随目标境界更换（丹药→仙草→九转丹→灵宝等），与宗门护道同源但按个人规模缩放，属弟子个人费用的一部分。

**费用与竞争**：传功是持续灵气开销，与口粮、建筑维护、凝石、加工共用灵气池，排在其后；护道是一次性材料开销，与宗门破境、弟子突破和制作竞争同一批材料。弟子逐境突破基础费用沿用现值（目标宗门费用的 1%），护道材料另计，不并入基础费用。

| 项目 | 设计值（试调） |
| --- | --- |
| 传功加速 | 个人修炼速度 +75%（约 ×1.75） |
| 传功灵气/秒 | 0.4 × 弟子有效境界倍率（约本人基础口粮的 1.6 倍） |
| 护道加成 | 按目标境界 +4～+10 百分点（见下表） |
| 上限 | 修为上限、99% 成功率与材料条件均保留 |

护道加成按突破目标境界配置，材料与加成为试调：

| 目标 | 材料 | 加成 |
| --- | --- | --- |
| 引气入体 | 灵气60 | +4 |
| 炼气期 | 灵草40 | +4 |
| 筑基期 | 丹药4 | +5 |
| 金丹期 | 仙草2 | +6 |
| 元婴期 | 仙草5 | +7 |
| 化神期 | 九转丹1 | +8 |
| 炼虚期 | 九转丹2 | +9 |
| 合体期 | 秘银6 | +10 |
| 大乘期 | 灵气分子20 | +10 |
| 渡劫期 | 灵宝1 | +10 |

**数据与存档**：`members[]` 增加 `mentored`（是否受传功，缺省 false）与 `aidBonus`（待生效护道百分点，缺省 0）；归一化清理非法值与超限，旧档默认关闭，不自动补钱或补护道，培养状态随保存、导出与离线副本保留。培养消耗逐人结算并计入灵气／材料出项，批量操作逐人扣料、不足即停、不超支。

**界面与验证**：弟子管理页每行提供传功开关与护道入口，详情提示显示传功消耗/秒、当前传功加成与待生效护道；增加“传功中”“已护道”筛选。验收：传功只加速修炼、不停岗、不改口粮与岗位产出；修为满不扣费；灵气不足停功不欠账；护道只作用于本人下一次突破并被清除；旧档不重抽；在线与离线一致。

原“培养设施、师承”等方案由上表取代：本轮不新增培养建筑，不引入自动突破；个人死亡、境界停滞与独立属性仍按 2.4 暂缓。

### 2.2 培养策略与低操作负担

- [ ] 明确重点培养人选及执行顺序，评估按灵根、岗位和进度选择人选的收益。
- [ ] 评估宗门下一境材料、口粮与个人培养预算的预留规则，避免批量培养耗尽经营资源。
- [ ] 决定是否提供自动突破，明确适用人选、目标境界、缺料处理及在线／离线一致性。
- [ ] 若引入自动推荐岗位，明确推荐依据，避免后台擅自打乱玩家分工。

现有审计中的“保留材料／直接培养”仅为模拟策略，不等于游戏已实现这些开关。

### 2.3 天赋升级与后续专长

首版获取、三条上限、类别互斥、个人效果、独立随机、旧档空天赋和组合筛选已实施；原天赋升级（随成功突破自动提升、Lv.1–Lv.3、品级固定）与天级岗位词条已实施，见 [DISCIPLE-TALENTS.md](DISCIPLE-TALENTS.md)。天赋类型固定，不洗练或替换。

- [x] 确定原天赋升级触发（40% 突破判定）、成长等级（Lv.3 封顶）、目标选择（最低级优先）及效果上限（类别上限随之上调）。
- [x] 决定升级不改变天地玄黄品级，保持固定天赋身份与专长。
- [ ] 结合当前低基础成功率、每境10个百分点指导和天赋加成，重测材料消耗与失败重修节奏。
- [ ] 实施后通过多种子审计评估是否调整升级概率或扩展更高等级。

当前只有阵徒、樵夫、矿工、采药人、悟道者和香使六类岗位，没有个人炼丹或炼器岗位。丹道、炼器类天赋若要影响共享加工，需先定义弟子如何参与产线及分配容量；不能默认按每名弟子叠加全宗制作收益。个人天赋也不能默认扩大为全局产出。

## 3. 数据、兼容与验证

### 3.1 当前数据契约

运行时以 `disciples.members` 为权威记录，`total` 与 `jobs` 为人数及岗位汇总。`nextId` 分配递增身份，`rootSeed` 保存灵根随机序列。

| 字段 | 当前含义 |
| --- | --- |
| `id` / `name` | 持久化身份与姓名 |
| `roleId` | 岗位标识，闲散为 `null` |
| `realm` / `cultivation` | 实际境界与本境修为 |
| `spiritualRoot` | 灵根标识 |
| `talents` | 固定天赋条目 `{ id, level }`，等级范围 Lv.1–Lv.3 |
| `mentored` / `aidBonus` | 是否受传功；待生效的个人护道百分点（0 表示无） |
| `cooldown` | 突破调息剩余秒数 |
| `residenceSeconds` | 入宗后累计已结算秒数 |
| `totalQiConsumed` | 累计个人灵气消耗 |

速度、有效境界、突破状态、费用及成功率动态计算，不保存 `cultivationRate` 或 `breakthroughStatus`。当前身份字段为 `id`，历史草案中的 `discipleId` 不作为新增字段要求。`talents` 已进入归一化；`talentSeed` 与 `talentVersion: 2` 保存于 `disciples`。旧弟子不补发随机天赋、不自动升级，种子缺失时从原灵根种子派生，不在重复读档时推进。

旧人数档按原人口与岗位补凡体、零修为个体；缺失停留与消耗补零，从更新后开始累计，不估算历史投入。已有有效记录保留。人数兼容接口按现有顺序补充闲散人选或移除超额人选，不自动挑选高境界者。

### 3.2 培养审计与结果边界

`npm run audit:disciples` 支持不突破（`off`）、预留宗门材料后培养（`protected`）、直接培养（`greedy`），可用随机灵根（`calibrated`）或固定三灵根（`triple`）对照；第 5 参为培养维度 `off`／`mentor`（传功）／`aid`（护道）／`both`，种子与培养维度都可逗号传多个做多种子×多策略对照。模拟只调用真实引擎操作，不提供游戏内自动突破。

历史结果见 [DISCIPLE-GROWTH-DATA.json](DISCIPLE-GROWTH-DATA.json) 与 [BALANCE.md](BALANCE.md)。早期样本采集于 2026-10-11、采矿场与药圃增产调整之前、单一种子；2026-10-13 增补手动培养（传功／护道）多种子审计，5 种子 × 4 策略 × 48h。各组宗门失败、退境与身死历史不同，结论只说明特定策略下的材料竞争与培养先后，不能直接代表当前版本或平均通关速度。

继续调数值前应重测当前建筑前置与经济配置，使用多种子、不同上线频率和培养策略；比较宗门推进、弟子成长分布、材料占用、断供、等待时间及单位人口净产能。首名高资质弟子的到达时间不能代替全体平均速度。

### 3.3 后续改动的验证要求

- 保持修为上限、宗门上限、个人有效境界与实际境界的区分。
- 逐人扣料与批量停止不超支，预览和执行使用同一费用及概率入口。
- 培养、修炼、调息、新人入门和资源消费使用一致的在线／离线时间轴。
- 随机结果持久化，迁移可重复读取而不重抽、不重复补发。
- 个人效果只作用于明确的人选、岗位或产线，避免重复计算宗门倍率。
- 大量弟子、批量操作和长时间离线正常结算，列表与加载提示保持可用。

现有回归入口见 `tools/disciple-check.mjs`、`tools/architecture-check.mjs` 与 `tools/dom-check.mjs`；验证命令统一见 [ENGINEERING.md](ENGINEERING.md)。
