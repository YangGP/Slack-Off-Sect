# 境界锁与科技链方案审核（2026-10-22）

> **原则**：
> 1. 金丹以前，用清晰的科技链引导玩家；
> 2. 金丹以后，只有**真正依赖某个修为阶段**的研究才保留境界门槛；
> 3. 其他研究依靠上游知识、特殊材料、科研投入与储存能力开放。
>
> 本文保留设计审核与历次执行过程；前七节为历史方案，后文为执行记录。当前修正与费用以[问题复核及改造记录](RESEARCH-CHAIN-REBALANCE-ISSUES-2026-10-22.md)文首及后附对照为准，历史统计不代表当前实现或平衡验收。

## 一、先定义“真正依赖修为阶段”

建议只用三条判据，避免“内容强所以加境界”重新长回来：

1. **对象只在该境界存在**：如元婴后才能分灵、炼虚后才能承灵能、合体后才能采仙灵力；
2. **境界是研究的主体**，不是研究的强度档位；
3. **低境界提前掌握会破坏叙事或顺序**，而不是仅仅“太快”。

不满足以上三条的，都不应使用 `needs.realm`；改用：
- 上游研究（`needs.upgrades`）；
- 特殊材料（配方产物，且来源研究先于节点）；
- 科研投入（灵机/知识材料费用）；
- 储存能力（仓容或仓储建筑）。

## 三、金丹以前的链式方案

当前有 5 个无前置根：灵源考、邻宗往来、矿脉经、百草辨、加固仓架。要让“科技链”清晰，先把 4 个支线根接回主链：

| 支线根 | 现状 | 建议 |
| --- | --- | --- |
| 邻宗往来 | 山门 ＋ 筑基 | 改为山门 ＋《香火愿》，移除境界 |
| 矿脉经 | 炼铁炉 | 追加《探矿术》 |
| 百草辨 | 药圃 | 追加《灵植术》 |
| 加固仓架 | 库房 ＋ 筑基 | 追加《土木术》，移除境界 |

建议的主链：

```
灵源考 → 观气法 → 灵气测定 → 凝气化液 → 凝液法 → 灵气纯化 → 凝晶原理
   ├→ 灵植术 → 炼丹术 → 探矿术 → 木作器械 → 土木术 / 炼器术 → 符文入门
   └→ 居所营造 → 凿石要诀 → 引泉净水 → 园林营造
```

关键节点：
- **观气法**是第一个分岔：灵气线与灵植线；
- **炼丹术**把灵植线接到探矿线，避免“百草辨/矿脉经”悬空；
- **炼器术**把木作、土木、炼丹汇合到符文线；
- **讲经法**把符文线接到观星/阵法；
- **筑基**不再是硬门槛，只是链上自然的阶段（材料、建筑、灵机投入）。

## 四、金丹以后的替代门禁

移除境界后，按以下顺序补门禁，优先级从高到低：

1. **上游研究**：每个节点至少有一个同线研究前置（已基本满足）。
2. **特殊材料**：费用中的灵晶、秘银、灵纹石、阵图、九转丹、仙草等，必须已有来源研究；`audit:sources` 的“来源晚于可见”清零。
3. **科研投入**：灵机与知识材料费用；注意费用不得超过灵机仓容，否则是“仓容硬墙”而不是投入。
4. **储存能力**：
   - 先用现有 `needs.building`（玄库、法藏、材料库、洞天）表达“先扩仓”；
   - 若需要“仓容达到 N”这种精确门槛，再新增 `needs.capacity`（资源→最低上限），不要在数据里用费用反推；
   - 新增字段需要同时改 `checkNeeds`、可见性、诊断与旧档迁移，成本较高，建议只在 1～2 个节点试点。

## 五、分阶段实施建议

### 阶段 1：只改数据（推荐先做）

- 金丹及以前：移除全部境界门禁；接回 4 个支线根。
- 金丹以后：只保留 6 个真实依赖＋观星术例外，其余移除境界门禁，先靠现有上游链与费用运行。
- 同步 `audit:sources`、`progression-reachability`，确认无环、无“来源晚于可见”。
- 不新增 `needs.capacity`；储存先用建筑与费用表达。

### 阶段 2：补储存/材料门禁

- 若阶段 1 出现“节点太早可点”，优先补上游研究或材料来源，不要直接加回境界。
- 确实需要仓容阈值时，再引入 `needs.capacity`，只用于 1～2 个节点。

### 阶段 3：UI 与节奏验证

- 研究页按“当前可达 / 下一阶 / 更远”分组，显示下一项所需上游，而不是把所有节点平铺。
- 金丹前只展开主链与当前分支；金丹后按“自研方向”折叠。
- 用短测验证：金丹前是否仍按链推进、金丹后是否出现“无门槛跳跃”、仓容是否成为实际卡点。

## 六、风险

1. **移除 32 个门禁会加速金丹后内容**：如果费用/材料不紧，玩家会提前点出高层研究；阶段 1 必须配合 `audit:sources` 和短节奏测试。
2. **支线根接回主链会延后外交/猎杀**：邻宗往来改挂香火愿后，外交可能从筑基推迟到金丹前；如果希望保留早期外交，可把它作为“世界功能”保留一个筑基门禁（白名单例外）。
3. **储存门槛没有现成字段**：`needs.capacity` 需要引擎、UI、旧档迁移三处改动；不要为了 1 个节点引入大机制。
4. **建筑境界仍会挡**：例如洞天/通天塔建筑自带合体/大乘门槛；研究提前解锁不等于可建造，需在 UI 中说明“研究已开、建造还需境界”。
5. **旧档兼容**：移除 `needs.realm` 不会回锁已研究项；新增上游前置会让未研究项更晚出现，需确认旧档不会出现“已研究但前置未满足”的异常。

## 七、结论

你的方向可行，但当前数据需要**大幅减法**：

- 金丹前：把 4 个支线根接回主链，取消境界门禁，用“观气→灵植/炼丹→探矿→木作/土木/炼器→符文→阵法”引导；
- 金丹后：39 个门禁保留 6 个真实依赖＋观星术例外，其余改上游研究＋材料＋投入＋储存；
- 先做纯数据阶段，不要一开始就新增 `needs.capacity`；用现有建筑与费用验证后再决定是否加字段。
