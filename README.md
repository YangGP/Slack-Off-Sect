# 摸鱼宗门 · Slack Off Sect

用 Vue 3 + Vite（纯 JavaScript）实现的修仙宗门挂机放置游戏，参考猫国的资源池、劳动力、叠加建筑与研究加工体系。

**在线试玩**：[摸鱼宗门](https://YangGP.github.io/Slack-Off-Sect/)。当前代码版本 **v0.423 · 渐进解锁、仓储调整与伐木增产**；页面右下角可查看更新日志，版本记录由 src/data/changelog.js 维护。

## 开发与检查

~~~bash
npm install
npm run dev          # 开发预览 http://127.0.0.1:5273
npm run check        # 编码、引擎、SSR、DOM检查
npm run build        # 生产构建到 dist/
npm run preview      # 预览构建结果
npm run docs:tables  # 从数据文件重新生成全量表
npm run clean        # 删除构建、测试与审计产物
~~~

## 玩法

开局吸取天地灵气，建设聚灵阵，用灵气催生灵木，再以80灵气和20灵木建首间茅屋。弟子有空房时自动前来，分配到阵徒、樵夫、矿工、采药人、悟道者和香使，取得原料与灵机，再推进研究、加工、营造扩仓和破境。每间茅屋均需灵气与灵木，费用按数量递增；采矿场开放矿石供给，点石成灵以矿石和灵气制作灵石。

宜居度管理人口负担：负值全局减产，富余增产，最高增减50%；拥挤时弟子岗位减半，严重拥挤可能流失并暂停收徒。居所营造补足已入住配套，生活建筑、工艺和法宝提供富余宜居度，前期以10%～20%增产为目标，中后期可达到50%。

弟子拥有独立姓名、境界和修为，工作与离线期间自动修炼，修满后单人或批量突破；弟子页按境界分类管理岗位与成长。个人境界提高自身岗位产出和口粮，宗门退境保留弟子境界，暂时降低有效加成。

新弟子入门时获得灵根，灵根影响修炼速度与个人突破成功率，不改变岗位产出与口粮；已有弟子补三灵根并保留培养进度。管理栏可组合境界与灵根筛选，按进度或速度排序。`npm run audit:disciples -- 72 12345 protected`模拟保留宗门材料的弟子培养策略，可改为`greedy`或`off`对照；这不是游戏内自动突破。

修真研究灵气、材料与经营，技艺和法宝提供增益。符文是技术，灵木和金属是载体；金丹发展阵基与玄钢，元婴发展灵液、灵晶与混灵土，后续以玄铁混灵土、秘银、玄金和晶银营造高阶设施。元婴离析分子、化神分流解离，湮灭炉自化神起开放，每座额外提供一层面向多数资源的独立产出乘区（香火、粒子链与灵能除外）；灵能待炼虚《灵能输配》接入应用。炼虚发现仙灵力，合体以聚仙阵量产。炼制页管理批量制作、自动加工及库存目标，左栏可自选快捷配方。

手动单份与批量制作即时扣料并出货；金丹起专业配方自动加工共用设施工位，旧版未完成订单继续加工，可暂停、恢复或取消。扩建增加吞吐，分配权重决定容量紧张时的份额。流水作坊、灵纹锯阵与灵火冶炼升级设备，凝液回流与晶纹精修减少耗料；炼制页显示容量、动力、冷却、投入缺口与库存缓冲。疾炼法提供更高速限，灵气超载与灵能驱动按额外负荷收费；节气满仓凝液独立结算。

破境按概率结算，各目标境界可选不同的护道材料与香火祈愿，失败投料不退回。金丹冲元婴起每次突破均有身死风险，炼虚前存活失败不退境，炼虚起存活失败通常退一境，定神守境可降低退境概率并保境；渡劫基础成功率10%，无应劫正愿时材料满配35%，应劫正愿5级且材料满配上限60%。身死保留已有永久积累，本次仙缘收益减半。

带维护费的设施可以停用，缺料时收益按实际供给缩放；分灵、偏极与湮灭的进料和出料随全局倍率同步提速。建筑成本指数增长，可拆除返还一半材料；法宝可重复祭炼。心有灵犀开放自动加工、优先配方与逐项材料保留。突破主材料分四档：筑基至元婴用丹药，化神至合体用灵液与灵晶，大乘用灵气分子，渡劫用飞升阵印。化神起可转世取得永久仙缘，合体起通过湮灭产线与相关研究固结稳定的飞升阵印，渡劫可飞升并取得道果；首颗道果永久开放重修自动加工与按仓储比例保留。成就保留行为记录，当前不提供产出奖励。

主循环与离线补算共用引擎。设置页支持下载和导入存档文件；存档位于浏览器 localStorage，按同源隔离。

## 目录与分析工具

src/data/ 定义资源、建筑、研究与配方；src/game/ 负责规则、状态、存档和格式化；src/components/ 与 src/styles/ 负责界面。tools/ 包含引擎、渲染与DOM检查，及共用 player-bot 的节奏和资源审计。

~~~bash
npm run audit -- stone 8                   # 资源流量与容量
npm run audit -- stone 8 --craft=50        # 临时改变点石成灵成本
npm run audit -- qi 8 --prod=spiritField:qi:0.1
npm run audit:economy                      # 成品容量、基础需求与去向
npm run audit:crafts -- 24 0               # 加工链与边际增益
npm run audit:buildings                    # 前置、来源与容量可达性
npm run audit:pacing -- 72 0 0 0           # 首次生产、建设与各境耗时
npm run audit:breakthrough -- aided 2 72   # 满配护道的真实引擎节奏样本
npm run audit:breakthrough-risk           # 退境、身死与重试次数的数学模型
npm run balance -- 24 0                    # 固定时长的资源快照
npm run balance:events -- 24               # 固定种子事件对照
npm run balance:visits -- 24               # 持续操作与间歇上线
~~~

模拟结果依赖策略、操作频率和初始永久加成，不能当成真实玩家的通关时间。工具参数与统计口径见工程文档。

## 调试页面

在浏览器开发者工具的 Console 中输入 `DEBUG` 并回车，打开调试页面。可搜索全部资源，输入目标数量后点击「应用」或按回车，包括未解锁资源、仙缘和道果。

修改立即保存，允许超过仓储；正常生产仍受仓储限制。数量必须是非负有限数字，且不超过安全整数上限；整件资源向下取整。点击「关闭调试」或刷新页面后入口隐藏，已修改的资源保留。

本地存档读取失败时，游戏推进、保存与调试修改暂停；在设置中导入有效备份后恢复。

## 部署与产物

推送 main 或 dev1 后，GitHub Actions 分别检出这两个分支并检查、构建，将 main 放在站点根目录、dev1 放在 `/dev/`，合并为一个 Pages 产物后一次发布；任一分支检查或构建失败则不发布。正式地址为 https://YangGP.github.io/Slack-Off-Sect/ ，开发预览地址为 https://YangGP.github.io/Slack-Off-Sect/dev/ 。Vite使用相对路径，可在子目录部署。

首次启用：先将包含预览隔离代码和新版工作流的提交推送到 dev1，再把新版工作流同步到 main，确保后续两个分支都使用合并发布流程。在 Settings → Pages 中选择 GitHub Actions；Settings → Environments → github-pages 如限制部署分支，须允许 main、dev1。配置见 `.github/workflows/deploy-pages.yml`。

开发构建注入 `VITE_DEPLOY_CHANNEL=dev`，显示预览标识，存档与旧代备份键使用独立的 `slack-off-sect.dev.*` 前缀，不自动读取正式存档；统计采集强制关闭且不弹授权框。正式构建保持原存档键与授权流程。同代存档仍可由玩家主动导出／导入，独立存储不等于禁止手动复制进度。

npm run clean 清理 dist/、dist-ssr/、.smoke*/、.early/ 和 .vite/。本地依赖 node_modules/、源码和正式数据表保留。导出的存档由用户选择保管，清理脚本不扫描存档文件。
