研究完成及每类建筑首次建成仅保存一个关键节点；突破和独立重置保留前后快照及 `transition` 结果，嵌套身死重置由突破前后快照覆盖。`summary.json` 的 `milestones` 给出节点或快照序号。

schema 7面向整体节奏：每个窗口输出一条 `window`，其 `flows` 数组包含全部资源收支，`pacing` 包含缺料、仓容不足、满仓、加工与建筑缺供的累计毫秒数；共用一个 `seq`、起止时间和阶段信息。5秒状态切换只在内存中累计，不写逐次 `interval`；累计时长不因压缩降低观察精度。保留阶段首次材料备齐、最后缺料、连续备齐起点与各资源最后备齐时间，汇总跨窗口或恢复时延续这些信息。

普通动作、配置请求、调用次数和逐笔资源变化不落盘。增加、减少分别保留，配方产量、手动／自动归因与损失仍可汇总，失败突破的扣费也进入收支。境界、在线状态变化及突破／重置快照、检查点、结束会提前结算当前窗口；跨边界的阻塞时段拆分累计，避免重算、漏算或跨阶段混账。

`seq` 仍是物理记录的连续编号，不是30分钟刻度。同一时刻可能另有快照、关键节点或检查点记录；通常半小时一条窗口汇总加一条快照，不能把全部记录理解为固定半小时仅一条。

保留研究、首次设施、突破、重置、解锁和异常节点；普通购买能力波动不再记录。快照只包含库存、仓容、产消率和人口分工，不重复保存完整加工计划、计时器与建筑对象。报告关注阶段耗时、产消、缺料、仓容不足、满仓和实际损失；`recordsByKind` 用于了解记录体积。普通动作的逐次调用轨迹无法还原，完整运行状态仅在恢复检查点保存。未更改5秒决策、游戏数值或记录预算。

实际增减是引擎写入库存的事实。连续生产与维护在引擎内按净额结算，因此同时发生的毛收支只标为模型；加工产量单独按配方汇总。重置发放及永久余额镜像恢复不应视为生产收入。损失已经反映于资源流水或未入库金额，不能再从期末余额扣一次。

阻塞与满仓时长按观察区间左端状态计算，在线一般为5秒边界，离线为近似边界；各资源可能同时缺料，时长不可相加为总等待。加工状态含“按当前速限运行”“待启用自动”等描述，不全部代表无法推进。材料备齐后经过时间也可能包括投资、护道或策略选择，不自动解释为机器人空等。

阶段期初期末由全局已对账流水推导；原始快照和全局期初／期末用于交叉检查。回退、身死、转世和飞升后的重复境界使用独立访问编号，重置过程归入离开的阶段。

## 暂停、恢复与重建

在记录目录放置 `STOP` 空文件，可在安全边界暂停。恢复前移除 STOP；沿用同一份已编译程序，不重建、不修改源码：

```powershell
node .smoke-balance-track/balance-telemetry.js --resume=".resource-records/<runId>/checkpoint.json"
```

恢复只允许额外调整 `--wall-seconds`（本次计算额度，上限7200秒）与 `--total-wall-seconds`（全程累计额度，上限604800秒，不能下调）。省略时沿用检查点预算；旧的 `wallSpent`、游戏状态、时钟与随机流均保留，显式增加累计额度会写入`wallBudgetChanges`，报告列出真实累计时间。游戏观察期限与已完成目标不能靠恢复更改。源码、bundle、Node版本或记录校验不一致会拒绝恢复。记录器仍为schema 7，但v13源码与v12指纹不同，必须新开样本；旧schema 3／4／5／6和旧v12检查点不可接续新源码，旧流水仍可只读重建。既有样本不删除、不拼接续跑。

只重建报告，无需重跑游戏：

```powershell
node tools/run.mjs resource-report ".resource-records/<runId>"
```

重建会检查流水校验和与序号、独立对账，再输出 `report.rebuilt.json` 和同套汇总／CSV。有 `result.json` 时同时保留策略与结算数据；缺少时只能恢复流水中已有的事实，不能补造策略轨迹或旧版未记录的指标。

退出码：0为目标完成且对账一致，1为错误或对账不一致，2为正常停止但目标未完成。预算截止、STOP中断与观察期限截止均保留已有数据；只有实际结算目标达成才标记完成。

现有入口使用 P1 策略，默认概率也从旧遥测的必成功改为自然概率；历史报告不能与新样本直接当作同策略对照。无引用的旧遥测辅助模块 `telemetry-lib.mjs` 已移除，原实现可查 Git 历史；正式记录仍由 `resource-recorder.mjs` 负责。
